# 0047 — 转发区的三个值都写名称，账号的值不再套框

- 状态：`已接受`
- 日期：2026-10-20
- 相关：[0045](0045-relay-value-copy-icons.md)（本条接着它：三个值各有复制图标之后，三行要读得成一组）、[0043](0043-relay-address-text-and-sync-text-button.md)（地址早就是纯文本，本条给它补上名称）、[0042](0042-relay-section-one-address-box.md)（端口收进地址、只在监听出错时才给「换一个端口」的决策仍然有效）

## 背景

0045 之后转发区是「地址 + 复制图标」一行，「用户名 值 图标」「密码 值 图标」一行。实机用下来又报了两件事：

1. **地址前面没有名称。** 下面两行都以「用户名」「密码」开头，地址那一行却是一个裸地址，读起来像三行里混进了一行没有标签的东西 —— 尤其卡片上方刚填过「地址」字段，读者会去比对这两处是不是同一件事。
2. **账号的两个值套着框。** `.relayValue` 原本带着 `1px` 边框、圆角和 `bg-layer-3` 底色，因为 0041 那版把账号当成三个可以逐个复制的「值块」显示。框在只读的生成值上说的是「这里可以点、可以填」，而它既不能点也不能填。

## 决策

### 一、地址也写名称，三个值排成同样的「名称 + 值 + 图标」

地址行改成 `.relayLabel` 的「地址」+ `<code className={css.relayAddress}>` + 复制图标，与下面两行同构。新增字典键 `relayAddressLabel`（「地址」/「Address」），两本字典各一条。

- **为什么叫「地址」而不是「转发地址」**：这一区的标题已经是「本机转发」，行内再加一次「转发」是同一个词重复三遍；而且上游字段的标签就是「地址」，两者指同一件东西，用同一个词才不会让人以为这是两个不同的地址。
- **被否决的备选**：不给地址名称，靠位置与等宽字体区分。那正是这次要修的样子；`<code>` 只是排法上的提示，读屏软件不会因此念出「地址」。
- **被否决的备选**：给整行加一个 `<label>`。`<code>` 不是表单控件，`<label>` 的 `for` 无从指向；一段静态文字的名称用不着表单语义。

### 二、账号的两个值去掉边框、圆角与底色

`.relayValue` 只剩字体与颜色（等宽、12px、`label-primary`），与 `.relayAddress` 排法一致：三个值现在都是「一行字」，框只留给了真正可以编辑的字段。

- **为什么去掉框是对的**：框在卡片里一直是「这是输入框」的信号（服务器那一区的地址、账号、密码、口令都带着同样的边框）。转发区的三个值由配置推出来、由宿主生成，一个字节都改不了，套上同样的框等于把只读值伪装成可编辑字段 —— 与 0043 给地址去掉框是同一条理由，只是当时只改了地址。
- **被否决的备选**：保留框、只把边框调淡。淡框仍然是框，问题不在深浅。
- **被否决的备选**：去掉框、改成 `bg-layer-3` 的浅底块。底色同样是一块「可以点」的形状，且会和卡片的 `<pre>` 输出块混淆。

## 影响

- **正面**：三行同构 —— 名称、等宽的值、复制图标，从左到右读一遍就知道每一行是什么、怎么取走。
- **正面**：转发区不再有任何「假装可以编辑」的形状；卡片里带框的只剩真正的输入字段。
- **负面**：字典净增一条（`relayAddressLabel`），两本字典加测试用的字典共三处要同步。
- **负面**：三个值都靠字号与等宽字体区分于正文，窄卡片上不再有框把它们圈在一起，视觉分组只靠 `6px / 14px` 的间距。间距将来若被统一成同一个值，两行账号会读成四个松散的值。
- **验证**：`pnpm run typecheck` 通过；`tests/relay-panel.spec.tsx` 断言地址行现在是 `<span class="relayLabel">Address</span>` 打头、三个复制图标各就各位。README 的卡片说明与「开启与复制」同步更新。
