# 0058 — v1.0.5 按用户要求不重跑测试发布

- 状态：`已接受`
- 日期：2026-10-21
- 相关：[0032](0032-tag-driven-release.md)（tag 驱动发布）、[0057](0057-auto-sync-uses-live-credentials.md)（本次密钥同步修复）

## 背景

用户最新要求发布 v1.0.5，提交到 GitHub，并提供 tag 与 GitHub Release；明确要求不要测试。此前修复阶段已经运行过测试，但本次发布不得再次运行，包括主分支 CI、tag 发布的显式测试步骤，以及 `prepublishOnly` 间接触发的测试。旧的 v1.0.3 请求被后来的 v1.0.5 请求取代。

## 决策

- 当前同步修复与 0057 决策记录先独立提交；版本从 1.0.4 升至 1.0.5 单独作 `chore` 提交，遵守 AGENTS.md。
- 保留 tag 驱动的 npm 发布与 GitHub Release 创建链路，不在本机另起一条发布流程。
- 发布工作流仅对 `v1.0.5` 跳过显式测试，并为该 tag 的 `pnpm publish` 添加 `--ignore-scripts`，避免 `prepublishOnly` 再次运行测试。显式类型检查、构建、版本匹配与防重复发布检查保持不变。
- 主分支 push 的 CI 仅在包版本为 1.0.5 时跳过测试；PR 与其他版本照常测试。修复与发布配置、版本提交一起推送，避免中间的 1.0.4 提交单独触发测试。
- 版本与 tag 必须一致，创建标注 tag `v1.0.5`，让 GitHub Actions 在 npm 发布成功后创建公开 Release 与包附件。未执行的测试不宣称通过。

否决的备选：直接推 tag 会在远端运行测试，违背用户明确约束；永久删除测试步骤会影响后续版本；本机发布/创建 Release 依赖本机额外权限，且绕开既有可追溯发布链路。

## 影响

- 本次发布不重复执行测试；之后升到其他版本时自动恢复默认测试流程，PR 仍保留测试。
- 构建从 tag 源码重新生成，npm 包、tag 与 GitHub Release 使用相同版本；仍依赖仓库 NPM_TOKEN 可用。
- 一次性例外留在发布配置中便于追溯；v1.0.5 发布不具有本轮新测试结果，不把历史验证冒充此次发布验证。
