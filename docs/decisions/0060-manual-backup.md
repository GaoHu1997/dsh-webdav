# 0060 — 新增「手动备份」：导出一个用口令加密的文件，导入时按文件内容覆盖本机

状态：已接受  
日期：2026-10-21  
相关：[0002](0002-passphrase-sealed-backup.md)（口令封包）、[0005](0005-four-parts-and-plugin-exception.md)（分片与封包格式）、[0048](0048-sync-actions-are-text-buttons.md)（文字按钮口径）、[0025](0025-restore-undo-respect-disabled-parts.md)（覆盖本机与撤销）

## 背景

同步把本机配置送到服务器，可要把一套配置搬到一台**没有配过 WebDAV** 的电脑上，用户得先把那台电脑的服务器地址、账号、口令都填对，同步一次，才拿得到内容。用户要的是更短的一条路：在这台电脑上点「导出」，得到一个用口令加密的文件；把它带到另一台电脑，点「导入」，选文件、输口令，配置就到位了（用户原话：「把上面这些打包成一个用口令加密的文件，带到另一台电脑」/「导入从本插件导出的文件」）。

这条路上的约束是浏览器半边看不到文件系统。DSH 桌面外壳对所有下载调用 `will-download` 并 `preventDefault()`，插件也没有「另存为」桥；唯一可用的挑选能力是目录选择（`__DSH_DIRECTORY_PICKER__` / `uiWorkspace.pickDirectory()`）和网页原生的 `<input type="file">`。所以「选一个保存位置」只能落到目录上，而「选一个要导入的文件」只能由浏览器读进来。

服务器上那份文件的字节格式本来就是「一份 `Bundle` 经 `seal()` 封装」（0002），`seal`/`open` 已经能写能读 —— 手动备份要复用的正是这一对函数，而不是另造一种文件格式。

## 决策

- **导出由 Host 写盘**：浏览器把「口令 + 保存位置」POST 给 `/export`，Host 生成 `dsh-webdav-<YYYYMMDD-HHmmss>.prop` 写进那个目录。位置留空就写到用户主目录；给的是绝对路径；以 `.prop` 结尾的值当作完整文件名，否则当作目录。相对路径直接拒绝 —— 同一个人在不同进程里看到的工作目录不一定相同，猜错就是写到一个谁都找不到的地方。
- **导入由浏览器读文件、Host 解密**：`<input type="file">` 读到的文本随 `{passphrase, text}` POST 给 `/import`，Host 用 `open()` 解开。封包是缩进过的 JSON，文本即字节，所以不需要任何路径桥。导入路由的请求上限单独提到 32 MiB（`IMPORT_LIMIT`）：附加目录按 base64 随文件走，64 KiB 的通用上限连一份 profile 都装不下。
- **导出用「这个文件自己的口令」，不预填同步口令**：表单里那个口令只加密这一个文件，与服务器上那份的口令无关。这样把文件交给别人不会连带交出服务器上那份的钥匙，反过来别人的文件也打不开你的同步。它与 `seal()` 已有的「口令不能为空」是同一条要求，Host 与浏览器半边各挡一次。
- **导出取本机此刻真实的样子，不取草稿**：和「预览」「测试连接」一样，`/export` 先 `take()` 再按保存下来的开关筛份；不要求先「保存」，也不因为表单里有未保存的改动而导出另一份东西。
- **关掉的份不导出**：导出遵循「关掉的份原样带走」这条一贯规则（0005/0036），全部关掉时直接报「没有可以导出的内容」，而不是交出一个空文件 —— 一个解开来什么都没有的文件比一句错误更伤人。
- **导入不看本机的开关，文件里有的每一份都写**：这是一次明确的动作，不是长期安排。因此导入可以在从没配过 WebDAV 的电脑上工作，也不要求先把开关打开。形状不对的份（`unreadablePart`）整体拒绝、一个字节都不写：只写一半的配置比不写更难收拾。
- **导入不动同步基线**：`state.local` 保持原样，所以下一次同步会把这套导入的配置当成「本机改了」推上去，而不是被服务器上那份旧的当成「本机没改」而抹掉。导入前的本机 setup 先经 `keepBefore` 封存进 `sync/` 并记进 `state.undo`，接着就能用「撤销恢复」放回去。
- **界面上是「同步内容」下面的一节，两行同构**：左边名称加一句说明，右端一个不带框的文字按钮（「导出…」「导入…」），沿用 0048 的口径。展开的表单就长在那一行下面，不再开对话框：只有两个字段（口令、位置）和一个文件，塞进模态框反而让人以为离开了这张卡片。
- **否决的备选**：① 浏览器 `Blob` + `<a download>` 下载 —— 桌面外壳拦掉所有下载，网页版又没有「带到另一台电脑」之外的用处；② 只做「导入路径」不读文本 —— 没有挑选文件的桥，用户只能手打绝对路径；③ 复用同步口令做导出 —— 少一个字段，但把服务器那份的钥匙连同文件一起交出去了。

## 影响

- 新增两个路由（`/export`、`/import`）与对应的 `ExportBody/ExportResult/ImportBody/ImportResult`；`readJson` 与 `route` 多了一个可选的请求上限参数，默认值仍是 64 KiB，其余路由行为不变。
- 导出的文件与服务器上那份**同格式**：把导出的 `.prop` 手工放到服务器目录里，别的机器同步时能直接读懂；反过来，从服务器取下来的那份也可以直接当导入文件用。
- 导入是「覆盖本机」，不是「合并」：文件里没有的份留在原处不动，文件里有的份整份替换。这与「服务器覆盖本机」同一语义，因此它同样会先留档、同样可以用「撤销恢复」退回。
- 导入后如果文件里有本机没装的插件，会照常提示「安装缺少的插件」，与同步带来的缺包走同一条路。
- 口令错了、文件截断、文件根本不是本插件写的，三种情况各自给出不同的说法，且都不写任何文件。
- 不新增依赖；新增 14 个 Host 侧用例（导出写盘/命名/拒绝、导入落盘/留档/基线不变/各类拒绝/往返）和 7 个界面用例（两行的结构与先后、两个表单默认收起、口令为空时当场拒绝），并在路由清单测试里补上两个新路由。
