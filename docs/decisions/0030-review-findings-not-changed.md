# 0030 审查里那些不改的发现

- 状态：已接受
- 日期：2026-10-16

## 背景

一次对抗性源码审查（读 `src/`、在 `.review-scratch/` 里写复现）提了十几条。大部分是真缺陷，已经逐条修掉并各自记了 ADR（0017–0029）。剩下这几条，复现要么不成立，要么把产品的既定语义当成了缺陷。

把它们记下来是因为「审查看见的东西」不自动等于「要改的东西」：不复查一遍的读者只能看到代码，看不到当时为什么判它不改。

## 决策

### 决策一、整份在别处消失会传播过去

复现：A 把本地某个分片删干净；B 同步后读到的包里没有这一份，于是 B 也把它删了。

**不改。** 服务器是镜像，不同步就会被复制的那一半永久分叉，而分叉不会自己收敛回去。删除因此必须传播，否则两台电脑各自以为对方没有那一份，下次编辑又互相覆盖回去。已经在 [0005](0005-four-parts-and-plugin-exception.md) 的「影响·负面」里承认这一点：这是本设计的取舍，不是疏漏。分片内部的逐行合并是另一件事，刻意不做（那样会让两台电脑的最终字节不同，镜像前提就破了）。

### 决策二、无 ETag 上一台机器的编辑成为败者

复现：A、B 都在一个不给 ETag 的服务器上；A 改了本机，B 也改了本机；A 先同步，B 后同步，B 赢（`Bundle.created` 更新），A 的编辑进了 `sync/this-computer`。

**不改。** 这就是「新者胜」规则在分片级别的一次正常执行，不是无 ETag 特有的问题（有时间戳的两台机器也会这样）。修 0017 之前真正坏掉的是另一件事：A 连**只有自己**的编辑都保不住，因为盲写之后的回读把它当成了别人的改动。修好之后该留的留住了，剩下的这个是合并规则本身的语义。想换成「本机编辑总能上服务器」，就得放弃镜像或者做细粒度合并，两者都不该由一次审查顺手定下来。

### 决策三、undo 之后状态仍说这一份「动过」

复现：恢复（restore）把服务器那份带进来，然后撤销（undo）把它放回去，状态仍报这一份 `localChanged`。

**不改。** 文件确实回到了恢复前的样子，服务器还是恢复后的样子 —— 下一次同步确实要调和这个分歧。报「动过」是实话。报完之后下一次同步就会 push，状态随即收敛到两边一致（实测：status 全部 `localChanged: false`）。在撤销里额外重建基线反而会把一个真实的分歧记成不存在，那才是下一个坑。

### 决策四、服务器上不是我们备份的文件时应当更早拒绝

复现：服务器文件打不开，同步抛错（`NotBackupError`）—— 复现自己没接住这个异常。

**不改。** 行为正是设计的：报错，并且指向「用本机覆盖服务器」这个显式动作。见 [0007](0007-never-silently-overwrite.md)。

### 决策五、「不记住密码」应当连内存里也不留

复现：设了 WebDAV 密码、不记住，期望同步失败。

**不改，而且这条已经按另一种方式处理了。** 「不记住」的含义是**不落盘**（[0019](0019-session-password-not-remembered.md)）：同一个 Host 进程里它照常能认证，Host 退出后需要重新输入。让它连内存里也失效，得到的不是更安全，而是一个「明明刚填过却什么都同步不了」的插件。

### 决策六、无 id 的 `insert:` 块应当按位置匹配

复现：两个没有内层 id 的 `insert:` 块，期望它们指向同一行。

**不改。** 期望本身就是被修掉的缺陷本身（两个不同的块共用一个键 `insert:?`，会互相覆盖）。修好之后它们按内容取身份键，见 [0023](0023-anonymous-insert-keys.md)。

### 决策七、状态文件丢了，本机的编辑不保证活下来

复现 `.review-scratch/merge5.spec.ts` S1：两台机器改了同一行的不同值，状态文件被删掉，然后同步 —— 本机那份被服务器替换。

**按既定语义不改成「本地必胜」，但不再静默。** 状态文件没了之后，哈希层面与「第一次加入这台服务器」完全一样，而这两种情况没有任何可用的区分信号：服务器上的副本可能是别人的（本就该让服务器赢），也可能是自己上次写的（那就该让本机赢）。选一边猜都有把用户的选择做掉的风险。

选的是安全的那一侧：照常让服务器赢，但**先把本机内容留档，并在通知里点名这份副本的路径**（`src/engine.ts` 的 `keepUnmerged`）。用户能看见自己被替换掉了什么，Restore 和 Undo 都能把它放回去。真正的第一台机器（两边本来就一样）不会多出一份没用的副本 —— 实测 `saved` 为 `undefined`。

**没选「拒绝同步」的理由**：那样新机器根本没法加入别人的文件夹，而缓存副本 `sync-server.dshsync` 存在与否不是证据（整个 profile 目录被复制过来时它也会在）。见 [0024](0024-adopting-server-keeps-local.md)。

## 影响

正面：这些判断有据可查，不必让下一个读者重新推一遍；真正的修复与刻意的取舍分得开。

负面：文档变长了；其中几条（尤其第一条）的取舍要在 README 里也说得直白，否则用户会把它当 bug 报回来。
