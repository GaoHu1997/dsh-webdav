# 0074 第三轮审查：转发断连、dismiss 入队、pnpm 进程树与客户端互斥

- 状态：已接受
- 日期：2026-10-24

## 背景

对 v1.2.1 的一轮全面测试：515 个既有用例全绿之外，用探测脚本实证了一个转发层行为，用三个审查通道（宿主端、客户端、文件层）各找到一批"测试照不到的时间维度"缺陷——并发、竞态、生命周期。其中最重的一条（同步写回覆盖并发编辑）单独立为 [0072](0072-merge-writes-check-mtime.md)，状态文件降级单独立为 [0073](0073-damaged-state-moves-aside.md)。本条收拢其余各项。

## 决策

### 一、转发在目标中途断开时切断客户端（relay.ts）

实证：目标服务器写完响应头、写半截正文后销毁连接，转发 neither 崩溃也不结束——客户端挂在半截响应上直到自己的超时，没有超时的 WebDAV 客户端永远挂着；转发的 120 秒 socket 超时也不会触发（socket 已死）。修复：`answer` 流挂 `error`/`aborted` 监听，未发头时以 502 拒绝、已发头时 `res.destroy()`。探测脚本从"10/10 挂到超时"变为"10/10 在一秒内失败"，且无未捕获异常。

### 二、`dismiss` 走串行队列（engine.ts）

`dismiss()` 是唯一不走 `guarded`/`serially` 的状态写者。与一次收尾中的同步并发时，它用同步开始前的旧状态整写回去，把刚落盘的 `local/remote/sum/server/blind` 基线回滚到上次同步之前。修复：包进 `guarded`（0018 的队列自然覆盖）。

### 三、pnpm 超时杀进程树、不再换候选重试（install.ts）

Windows 上 `.cmd` 经 `shell:true` 启动，`child.kill()` 只杀 cmd.exe，真正的 pnpm 孙进程继续安装；超时又被当作"这个候选不行"，循环再起一个 pnpm，两个安装器并发操作同一 `node_modules`。修复：Windows 用 `taskkill /pid <pid> /T /F` 杀树；超时落入 `TimedOut` 标记，循环到此为止，超时原因原样报出。另外，退出码非零但清单要求的包都在时，`ok` 仍为真，但输出末尾透出退出码——"装上了，pnpm 自己认为有事"不该被读成"一切正常"。

### 四、客户端：一次只跑一个动作、失败的保存不清表单（card-store.ts）

- `run()` 入口加 busy 守卫（`runExport`/`runImport` 本就有，其余没有）：三个常驻提示的 ✕ 在长动作飞行中可点，两个动作交错后先完成者提前清空 busy，按钮在原动作未结束时恢复可点。
- `run()` 改为回答成败；动作后的 `load()` 只在成功时发起——**保存被拒后读回旧配置会把整份表单抹掉**，只剩一句错误。
- `load()` 补上 `reloadStatus()` 早有的 dirty 保护：动作期间输入的内容不再被动作后的重置清掉。
- 「状态刷新失败」行的 ✕ 原来绑 `closeMessage()`，清的是另一个字段，形同虚设；新增 `closeError()`。
- `pickFile()` 加序号（连续换选文件时慢的先读完不再覆盖后选的）与 32 MiB 上限（先拒后读，不在浏览器里冻结页面）。
- 动作请求加 10 分钟兜底超时（`action()`）：挂死的请求不再把 busy 永久卡死；超时文案说明宿主可能仍在执行。
- `adopt()` 对旧宿主的字段兜底补齐（`rememberPassword`/`models`/`plugins`/`patch`/`autoEvery`），与 `dirs`/`keys` 的既有兜底一致；Plugins 页的 summary 座也做首次状态读取；`preview()` 不再把 `reloadNeeded` 顺手清掉（磁盘真的变了，这个提示不该被一次预览抹掉）。

### 五、零碎修正

`writeAtomic` 的 fsync 见 [0073](0073-damaged-state-moves-aside.md)；`undo` 遇 `PassphraseError` 的文案改为指向本地副本与 `sync/` 目录（原文案说"服务器上的文件"）；`restore()` 开头一处永假的外层条件删去；`wire.ts` 里 preview 路由的注释 GET 改 POST。

## 影响

- 好的一面：转发层不再有"无声挂死"路径；状态文件只有一个写者队列；Windows 上不会再出现两个 pnpm 并发；客户端的三处"精心设计只覆盖了轮询路径"的盲区补齐。
- 代价：动作在 busy 时被忽略而不是排队——对提示 ✕ 这是想要的行为，对误点的动作是丢一次点击（按钮大多已禁用，丢的是 UI 之外的入口）；10 分钟超时后宿主可能仍在执行，文案已说明，重试仍由串行队列在宿主端兜底。
- 本轮明确不改的：附加目录对云盘占位符（OneDrive 等 reparse point）的静默跳过——需要改 wire 协议才能"可见"，留待单独立项；插件级 Config 的 `autoEvery` 是死配置——0009 已记载，删除属于公开配置面的变更，留给用户决定。
