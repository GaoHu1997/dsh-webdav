# 0048 — 六个同步动作全部是不带框的文字按钮，颜色按「这一次会动谁」分组

- 状态：`已接受`
- 日期：2026-10-20
- 相关：[0043](0043-relay-address-text-and-sync-text-button.md)（本条把它第二节「只有『立即同步』一个文字按钮、并且是这一行唯一着色的一项」推广到整行）、[0031](0031-card-layout-and-chinese-messages.md)（本条推翻它决策八「其余动作一律 `outline`」中关于同步动作的那一半；「每张卡片只有一个实心主操作」仍然有效）

## 背景

0031 决策八把这张卡片的按钮收成两种形态：一个 `primary`，其余 `outline`。0043 为「立即同步」开了一个口子，把它改成带强调色的文字按钮，其余五个仍是描边框。

实机截图里于是出现一半有框、一半没有的一行：**测试连接**、**预览**、**服务器覆盖本机**、**撤销恢复**、**本机覆盖服务器**都带框，中间夹着一个蓝色的裸字「立即同步」。用户的原话是「这个同步相关的操作按钮只改了一个，需要都改成 文字按钮，并且给出合适的颜色配色」—— 也就是把 0043 那一处没有推广完的改动补完，并且要颜色，因为不带框之后六个动作会退化成一行排在一起的六个词组。

## 决策

### 一、六个动作统一成 `ghost` + `.textAction`，不再有描边框

`check`、`preview`、`syncNow`、`restore`、`undo`、`upload` 全部从 `variant="outline"`（`syncNow` 原是 `ghost` + `css.syncAction`）改成 `variant="ghost" size="sm"` 加 `className={css.textAction}`。`.footer` 里不再有带框的按钮。

- **`ghost` 而不是原生 `<button>`**：要的是原语的悬停底色（`--dsw-alias-interactive-bg-hover`），并且 0043 已经在这个文件里为它补了焦点环。
- **`height: auto` + `min-height: 24px` + `padding: 0 6px`**：`size="sm"` 的 28px 高盒子是给有框按钮的，六个标签要挤在一行里，所以高度让位给文字本身；24px 的下限是让悬停底色不至于贴在字上。`.footer` 的 `gap: 2px` 加上每个按钮自己的 6px 内边距，相邻标签之间是 14px —— 没有框之后，间距就是唯一的分隔手段，太紧会被读成一个词组，太松这一行就会换行。
- **`font-weight: 500`**：12px 的普通字重在正文旁边与正文没有区别，光靠颜色区分不出一「排控件」和「一句话」。500 是这一行自己的一档，不用加粗（600）去和标题抢。
- **被否决的备选**：保留描边框，只给「立即同步」以外再加一两个文字按钮。那正是用户截图里那个「只改了一个」的现状。
- **被否决的备选**：六个都做成 `outline`，靠粗细或图标区分。框就是被点名嫌丑的东西，加图标则要在六个短标签前面各塞一个图形，行宽立刻不够。

### 二、颜色说的是「这一次会动谁」，不是重要性

| 动作 | 颜色 | 理由 |
| --- | --- | --- |
| 立即同步 | `--dsw-alias-state-business-primary`（强调色） | 这张卡片的正事；整行唯一的强调色，没有框也能一眼找到 |
| 服务器覆盖本机 | `--dsw-alias-state-warn-label`（警告色·文字档） | 用一边整体替换另一边 |
| 本机覆盖服务器 | `--dsw-alias-state-warn-label`（警告色·文字档） | 同上，且写的是服务器 |
| 测试连接 | `--dsw-alias-label-primary`（普通文字色） | 只读，不改任何一边 |
| 预览 | `--dsw-alias-label-primary` | 只读 |
| 撤销恢复 | `--dsw-alias-label-primary` | 把一份备份放回去，不动另一边 |

- **为什么只分三档、不是六种颜色**：一行里六种色相就是一排彩灯，读不出任何优先级，反而比描边框更吵。三档正好对应「正事 / 会覆盖一边 / 只是看看」这三件不同代价的事，而且每一档里的动作在语义上确实是一类。
- **为什么两个「覆盖」用警告色而不是错误色**：两者都可逆 —— 恢复有「撤销恢复」，上传会把原文件先封进 `sync/`（[0007](0007-never-silently-overwrite.md)）。红色说的是「这一步之后就回不来了」，而这里回得来。警告色是设计系统给「值得停一下但不必害怕」的那一档。
- **为什么用 `warn-label` 而不是 `warn-primary`**：设计系统把这两档分开了 —— `warn-primary`（`--dsw-static-amber-500`，`#f59e0b`）画状态点与 `Tag` 的底色，`warn-label`（`--dsw-static-amber-600`，`#dd8629`）才是警告**文字**用的那一档，`Toast` 的图标与 `ConnectionIndicator` 的警告文字都用它。两者放在浅色卡片上都不算高对比（`#f59e0b` 约 2.2:1、`#dd8629` 约 2.8:1，都低于正文的 4.5:1），这是这套调色板里警告色本身的上限；既然两档都过不了正文线，就取设计系统明确定为「文字」的那一档，读起来更稳，也不会和状态点/标签的观感混起来。真正的护栏不是这一行字色，而是点下去之后那个说清「会用哪边覆盖哪边」的确认框。
- **为什么「撤销恢复」不跟着染成绿色或强调色**：它是补救动作，不是正事；而且它大多数时候是 disabled 的（没有可撤销的恢复时），一个常驻的彩色 disabled 按钮只会让人去点它。
- **为什么「测试连接」「预览」不用 `--dsw-alias-label-secondary`**：次级灰在正文里读起来像说明文字，而这六个都是能点的按钮；不带框之后，颜色是「这是按钮」的唯一静态证据，所以最安静的两个也留在 `label-primary`。
- **被否决的备选**：把「本机覆盖服务器」单独升成错误色。它确实是这一行里代价最大的一个，但代价大的原因与「服务器覆盖本机」相同（都会用一个整体替换另一个整体，都留了退路），拆成两色等于说它们不是一类事。真正的护栏是确认框，不是颜色。
- **被否决的备选**：给每个动作各配一个图标来替代颜色。六个图标要新引入六个名字，卡片顶部已经有一排设置控件，视觉重量只会更高。

### 三、悬停与聚焦各自带一点本档的颜色

`.textAction:hover` 用 `--dsw-alias-interactive-bg-hover` 打底（来自 `ghost`），文字保持本档颜色；两个「覆盖」的悬停底色是 `color-mix(in srgb, var(--dsw-alias-state-warn-label) 10%, transparent)`，让指针停在警告项上时底色也在说同一件事。`:focus-visible` 由 0043 补的那圈 `--dsw-focus-ring-color`（缺省回落到 `state-business-primary`）负责 —— `ghost` 自己没有焦点环，键盘用户没有指针可用来发现按钮。

### 四、0043 与 0031 的口径怎么改

- 0043 说「它仍然是这一行里唯一着色的一项」。改成：**立即同步仍然是这一行里唯一的强调色（蓝色）**；两个「覆盖」带的警告色是另一层级的信息（代价），不是强调。
- 0031 决策八说「其余一律 `outline`」。「其余」里的同步动作这一半被本条取代；卡片最外层的「放弃改动」、通知里的「知道了」、确认框的「取消」、附加目录行尾的「移除」仍是描边 —— 它们不在这一行里，也不与这六个动作并列，这一轮没有动。

## 影响

- **正面**：这一行现在只有一种控件形态，不再一半有框一半没框；六个动作靠颜色的三档分组读得出来，而不是靠六个框一模一样地排着。
- **正面**：这一行的高度从 28px 降到 24px，六个标签在同样的宽度里余量更大，「服务器覆盖本机」这种长标签也更不容易被挤到第二行。
- **负面**：没有任何框之后，颜色成了「这是按钮」的主要线索。若将来有人为了某个主题把这些颜色改成与正文相同，这一行会立刻退化成一排看不出能点的文字，而现有测试只驱动 `card-store.ts`、不渲染 TSX，拦不住这一类回归（这一条与 0043、0045 记下的同一种负面是同源的）。
- **负面**：`font-weight: 500` 让这一行比正文重一档，卡片底部因此比它上方的小字更「响」；这是为了让六个裸字仍然像控件而付的代价。
- **负面**：颜色分档本身需要解释一句（「为什么这里有个橙的」），本决策就是那句解释；不读文档的人可能仍会把橙色读成「坏了」。
- **验证**：`pnpm run typecheck`（`tsc -p tsconfig.client.json --noEmit`）通过；`tests/client-card.spec.ts` 与 `tests/relay-panel.spec.tsx` 共 51 例全部通过（前者只驱动 `card-store.ts`、后者渲染的是转发面板，都不涉及这一行按钮的 DOM）。`pnpm test` 全量跑时 `tests/relay-host.spec.ts`、`tests/relay.spec.ts` 有若干 `Test timed out in 5000ms`，用 `git stash` 单独暂存本轮两个 UI 文件后同样复现、且失败用例名随运行次序漂移 —— 属于本工作区里尚未提交的转发改动的既有不稳定，与本条无关。README 的卡片说明同步更新。
