# 0062 — 手动备份的落盘确认、接口协议与配置页视觉层级

- 状态：已接受
- 日期：2026-10-21
- 相关：[0060](0060-manual-backup.md)（备份由宿主写入）、[0061](0061-prompts-live-under-the-sync-actions.md)（同步动作提示的位置）

## 背景

用户报告点击导出后找不到文件、出现 HTTP 405 且响应非 JSON，并指出配置页标题小于正文、辅助说明过大、章节边界缺失而内部横线过多、图标比例失衡。当前运行宿主的 `/plugin/webdav-sync/export` 在验证目录能返回 JSON 200 并生成加密文件，因此未复现原始 405，不能把它归因于 WebDAV、加密算法或断言某个宿主版本有缺陷。

排查确认了三个独立问题：第一次「导出…」仅展开表单，用户还需填写独立口令并确认，页面未充分说明文件由运行 DSH 的电脑保存而非浏览器下载；导出路径通过“有无扩展名”区分文件和目录，带点目录会被误判，已有目录可能写入失败，尚不存在的带点目录会被直接写成文件；秒级文件名及普通写入可能覆盖已有备份。另外，客户端信任任意 JSON 成功响应，宿主路由未限制 HTTP 方法，目录选择失败被静默吞掉。

## 决策

1. **保留宿主落盘机制，不引入浏览器下载桥接。** 表单文案明确先展开、填写口令、再「生成备份文件」；成功报告实际绝对路径、大小和内容，说明文件在运行 DSH 的电脑，不在下载列表。保存位置必须绝对路径；留空仍是宿主用户主目录。目录选择失败显示手动填写建议。
2. **按文件系统状态和 `.prop` 区分导出目标。** 已存在的目录始终当目录，包括带点或以 `.prop` 结尾的目录；新路径只有 `.prop` 才作为完整文件名，其余均作为目录。自动名称采用毫秒时间戳加 UUID 短后缀，写入使用 `wx`；拒绝覆盖任何已存在文件。这是对 0060 显式文件路径能力的安全收紧，不修改备份格式、独立口令或同步基线。
3. **HTTP 错误是失败，不是假成功，也不自动重试写入。** 客户端保留宿主 JSON 错误；非 JSON 错误带方法、接口路径和 HTTP 状态。401/403 提示重新打开登录页面，404/405 提示刷新、重载插件或重启并核对前后端版本。不改成 GET、不切换到未经授权的其他地址、不把这类错误称为远端 WebDAV 返回。导出响应必须有非空路径、正整数大小及有效内容清单；导入必须有有效份名、变更/安装状态和创建时间，异常成功响应不清空表单或显示成功。
4. **宿主 status 只接受 GET，所有动作只接受 POST。** 错误方法返回 JSON 405 和 `Allow` 且不执行动作。请求体必须 JSON 对象，备份字段若存在必须为字符串；超限请求限量缓存后继续消耗请求流，结束后返回 JSON 错误，不销毁连接导致客户端看见断连。导入 32 MiB、其余 64 KiB 的上限不变。客户端忙碌期间拒绝重复备份提交。
5. **统一配置页局部视觉规则，不修改宿主全局主题。** 章节标题 15px/600/22px，字段与控制正文 13px/20px，说明和状态 12px/18px；用主题色区分主次。章节顶部分隔线与间距统一，首章除外，减少行内横线；刷新/复制 SVG 14px，保留独立点击区域。表单、状态、备份和转发共享节奏；窄屏布局、键盘焦点与 reduced-motion 一并覆盖。保留 0061 的提示归属、顺序和预览层级，不另造章节。
6. **手动备份两行的按钮去掉省略号。** 「导出…」/「导入…」改成「导出」/「Import」这样的纯动作名：省略号在这里只表示「点开还有一步」，而这一行右端的按钮本来就是展开一个表单，不是打开对话框；把「点开还有一步」写进按钮本身反而让没有统一小三角的文字按钮看着像缺了图标。展开出来的表单里另有「生成备份文件」这个真正的确认动作，语义更准。

## 影响

- 手动备份仍不依赖 WebDAV 账号，导入仍使用文件口令并保持同步基线；未保存的同步开关不决定导出内容，文案明确按已保存项导出。
- 用户指定已有文件时需换名，不再隐式覆盖；生成文件名略长换取不碰撞和保护历史备份。
- 新增真实 TCP HTTP 回归：客户端 API → 注册宿主路由 → 加密文件落盘 → 错口令不写 → 第二 profile 正确导入。另覆盖非 JSON 405、成功响应校验、失败表单保留、重复提交、目录选择错误、带点目录与不覆盖，以及布局结构与样式规则。485 项测试、类型检查和前后端构建通过；实际组件的隔离 Chromium 预览确认标题 15px、输入正文 13px、图标 14px，1100px 与 390px 视口均无水平溢出或页面异常。这不是当前 GUI 已加载新版的证明。
- 原始 405 的部署/宿主触发条件仍未确认；这些改动提供协议约束、可操作诊断和回归防线，不能宣称复现并定位了该次事件。
- 不修改依赖或 package.json 的版本；客户端和宿主均需重新构建并一起加载，旧宿主不会因仅刷新页面而替换已加载的 Host 模块。
