# 0067 — 「API 密钥」排到第二行、手动备份改用图标、转发密码脱敏展示

- 状态：已接受
- 日期：2026-10-22
- 相关：[0054](0054-sync-api-keys.md)（新增「API 密钥」一份）、[0060](0060-manual-backup.md)（手动备份）、[0062](0062-backup-protocol-and-settings-hierarchy.md)（手动备份两行的按钮与配置页视觉层级）、[0047](0047-relay-labels-and-no-value-frames.md)（转发三个值都写名称）

## 背景

用户对同一张卡片提了四点：

1. 「同步内容」里「API 密钥」这一行要移到第二位。
2. 这一行的说明只讲密钥本身，不要附带别的废话。
3. 手动备份的导出/导入从文字按钮换成图标，并紧跟在该行名称后面。
4. 本机转发的密码要在界面上脱敏，点复制图标时仍然复制真正的密码。

当时的状态：各份的展示顺序就是 `PARTS` 的顺序，而 0054 把 `keys` 追加在数组末尾；手动备份两行右端各是一个 28px 的文字按钮（0062 决策 6 刚把「导出…」的省略号去掉）；转发区的密码以等宽原文排出来，和地址、用户名一样既可读也可选中。

## 决策

1. **顺序只改一处：`PARTS` 变成 `['models', 'keys', 'plugins', 'patch', 'dirs']`。** 卡片行序、合并顺序、`/status`、`/preview`、导出文件的份清单都读同一个数组，所以「密钥排第二」是这一处改动的结果，而不是界面层的单独排序。密钥属于它们点名的那些供应商，把两行放在一起读更顺。否决了在客户端把 `keys` 提到第二位的做法：那会造出第二个真源，两边迟早不一致。也否决把 `dirs` 一并提前 —— 附加目录是「这台电脑额外带哪些目录」，不是 profile 的一份。
2. **密钥行的说明只讲密钥。** 中文改为「本机存的 API 密钥，按供应商名字对应；两边都改过时以本机为准，同步不会删掉任何密钥。」，英文同步改写。删掉原来那句「离开本机前同样用口令加密」：加密是导出这个动作本身的事，`exportHint` 已经在讲；在这一行重复它，读者会以为密钥有单独的口令。
3. **手动备份的动作改成紧跟名称的图标。** 新增模块内的 `RowAction`：`Tooltip` 包一个 `variant="ghost" size="sm"` 的 `Button`，`icon` 为 `IconDownloadOutlineRegular`（导出）或 `IconUnarchiveOutlineRegular`（导入），位置在 `.backupHead` 里紧接 `.backupTitle` —— 和「附加目录」把「选择目录」放在名称右边是同一个位置。屏幕上不再出现第二个「导出/导入」字样（这一行已经有同名标题），名称交给 `aria-label` 与 tooltip。`exportHint` 相应改成「点标题旁的图标，填好口令后确认」。尺寸沿用卡片其它图标动作的 24px 见方（`.page button.backupIcon`），而不是 primitive 的 28px 盒，免得标题行高过下面那句说明；点击区域、焦点环与 tooltip 都还在。否决继续用文字按钮：那会把同一个词印两遍；也否决把图标留在行尾 —— 按钮离它作用的标题太远，读起来像第二个不相关的动作。
4. **转发密码显示固定的一串点。** `PASSWORD_MASK = '••••••••'`（固定八个，不按真实长度生成：长度本身就是信息，而且每次渲染都要算），该 span 标 `aria-hidden="true"`，免得读屏把八个圆点念出来。复制图标拿到的仍是 `view.password` 本身（值从状态直达 `writeClipboard`，从不写进 DOM），所以「显示什么」与「复制什么」不会漂移。地址与用户名保持可选中的等宽文本：它们本来就是给人看、给人手抄的。同时把复制失败的提示从「请手动选中复制」改成「请再点一次」—— 密码已经选不中了，原来的建议不再可行。

## 影响

- 行序改动落在 `src/wire.ts` 的 `PARTS` 上，所以凡是按份顺序输出的地方（状态行、预览的「哪几份」、导出文件的 `parts`）都跟着变；`keys` 不再排在末尾。
- 密钥行的提示短了，也不再声称密钥另有口令；导出这一步的加密仍由 `exportHint` 与表单本身说明。
- 手动备份的两行从「名称 + 说明 + 右端文字按钮」变成「名称 + 紧跟的图标 + 说明」，`.backupAction` 的 28px 文字按钮样式随之删除，新增 `.page button.backupIcon`；导出/导入的表单、口令、落盘行为一个字节没动（仍是 0060/0062 的那套）。
- 密码在界面上不再有原文，截图或旁人瞄一眼都带不走它；代价是它也不再能手动选中复制，复制被系统拒绝时只能再点一次。需要原文的场合，本来也是从转发账号那一侧配置里取。
- 测试同步更新：「同步内容」各行的顺序、手动备份两行的形状（图标、`aria-label`、无第二个可见标签）、样式契约里的 SVG 计数（4 → 6）与 `.page button.backupIcon`、以及转发密码脱敏（不得出现原文、必须出现圆点且仍在同一对里跟着复制按钮）。505 项测试、客户端与宿主两侧 `tsc` 与 `tsdown` 客户端构建全部通过。
- 另用隔离 Chromium 渲染这张卡片核对行为，不只是看形状：行序为 模型供应商与模型 → API 密钥 → 已安装插件 → 其余 profile 配置 → 附加目录；两个备份图标各 24×24、`aria-label` 为「导出 / 导入」；转发密码一栏的文本是八个圆点，`document.body.innerHTML` 里搜不到 `example-password`；点密码旁的复制图标，`writeText` 收到的是 `example-password` 本身（用户名与地址各自的图标同样交出自己的值，作对照）；1100px 与 390px 视口都没有横向溢出。这是隔离页面的结论，不代表当前 GUI 已加载新版。
- 仓库里没有 DOM 测试环境（vitest 跑在 node 下，没有 jsdom/testing-library），所以「复制到的是真密码」在**单元测试**里只能按结构钉住：同一个状态值、圆点是常量、两者不经过同一条路径。真正「点了复制拿到原值」那一半由上一条的浏览器核对覆盖，不是测试覆盖。
- 不改依赖，也不改 `package.json` 的版本号；客户端与宿主半边都要重新构建并一起加载。
