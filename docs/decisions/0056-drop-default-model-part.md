# 0056 — 默认模型不再是一份，「附加目录」默认不勾

- 状态：`已接受`
- 日期：2026-10-21
- 调整：[0005](0005-four-parts-and-plugin-exception.md) 定的 `models/defaults/plugins/patch` 四份里的 `defaults` 一份；顺带改 [0036](0036-extra-directories-part.md) 那份的开关默认值

## 背景

用户 2026-10-21 的原话，两条：

> 1.同步内容移除：默认模型(每次更换模型都会导致同步，而这个没有实际意义)
> 2.同步内容默认不勾选 附加目录

第一条不是「这份有问题」，而是**这份的粒度与它的改动频率不匹配**。`agent-default-model` 那一行装的是「新会话用哪个供应商、哪个模型、思考强度多高」——它被改动的时机不是「配置变了」，而是「这一次想用别的模型」，一天可能好几次。而同步的判据是「这一份的哈希与上次同步时不同」：每换一次模型，`defaults` 的哈希就变一次，下一次同步就把「本机有改动」报出来、并往服务器上推一次新文件。

代价与收益的方向是反的：

- 那一行的内容几乎没有跨机价值。「这台电脑上默认用哪个模型」是每台机器自己的偏好，不是需要共享的 setup——一台桌面机和一台笔记本本来就不该被强行拧成同一个默认模型。
- 它带来的代价却是持续的：每次换模型都多一次同步，多一份 `sync/` 留档，多一次「服务器覆盖了本机：默认模型」的通知。用户看到的是「我什么都没同步，它自己就在同步」。
- 而且这次同步推送的那份文件里，其余五份可能一个字节都没变——整份上传只为了一个模型名。

第二条是另一件事：`dirsEnabled` 自 [0036](0036-extra-directories-part.md) 起默认 `true`，意思是「这台电脑带附加目录」，可一台刚装好的电脑**一个目录都还没指定**。默认开着等于让一个空列表也算「这一份参与同步」，而附加目录是**整份带走**的东西（最多 5 个目录、每个 2000 个文件 / 8 MiB）：没有明确指名，就不该有东西被读、被写。

## 决策

### 一、`defaults` 从 `PARTS` 里去掉，而不是默认关掉

可以保留这一份、只把 `SyncConfig.defaults` 的默认值改成 `false`。否决它，理由是：默认关掉的份仍然占着一行开关、一个 `PartView`、一条 `PartHashes` 字段、一处 `syncsPart` 分支，以及一条「关掉的份原样带走」的合并路径——这些都是为一个已经被判定没有价值的粒度付的钱。而且默认关只会把问题从「换模型就同步」变成「换模型就出现一条本机有改动的假状态」，人还是得去理解它。

所以：`PARTS` 变成

```ts
export const PARTS = ['models', 'plugins', 'patch', 'dirs', 'keys'] as const
```

（`src/wire.ts:90`，原来 `'defaults'` 在 `'models'` 之后）。`DefaultsPart` 这个类型整个删掉，`Bundle`、`PartHashes`、`SyncConfig`、`ConfigView`、`ConfigureBody` 里对应字段一并删掉，`Collected` 少一个可选字段，`viewOf` 少拷一个，`configure` 少接一个。

### 二、`agent-default-model` 那一行**也不进 `patch` 份**

这一条是这次真正需要想清楚的地方。`collect()` 把「除了模型行与插件自己的行之外的所有 loader 行」收进 `patch` 份（`src/store.ts:167`）。`defaults` 不再是一份之后，那一行会**自动落进 `patch`**——于是换一次模型，`patch` 份的哈希也变一次，第一条要修的问题原样搬家到了隔壁。

所以 `collect()` 的过滤条件里 `id:${DEFAULTS_ID}` 必须留着（`src/store.ts:167`）；同理 `applyPatch()` 的 patch 镜像里那两处「模型行、默认模型行、本插件的行原地不动」（`src/store.ts:295`、`src/store.ts:308`）也必须留着，否则一次同步会把别处传来的 `patch` 条目铺过来时顺手挪走或删掉这一行。

`DEFAULTS_ID` 常量因此留着，但它的注释改成了「**只为了把它排除在同步之外**才读它」。它现在的处境和 `SELF_ID`（插件自己的 loader 行）完全一样：是本插件**永远不带走、永远不写**的行。

这一行留在各自的电脑上，跨机不同步，也不需要任何开关——它本来就没有「要不要带它」的问题了。

### 三、「附加目录」默认不勾

`defaultConfig()` 里 `dirsEnabled` 从 `true` 改成 `false`（`src/state.ts:66`）。因为 `normaliseConfig()` 的 `flag(key)` 在键缺失时回落到 `defaultConfig()` 的值，这一改**同时**让旧 `sync.json`（没有这个键）读成关——不需要迁移代码，也不需要写盘。

浏览器半个边跟着改两处：`EMPTY` 的占位值（`src/client/card-store.ts:239`）与 `adopt()` 里对老宿主的 `?? false`（`src/client/card-store.ts:325`）。后者的注释说清了道理：一个早于这个开关的宿主不会发这个字段，而「关」是这一份的静止状态，读成开会让一张卡片在什么都没说的情况下把一个目录画成正在同步。

注意 `keys` 的 `?? true` 与此**不同**，没有跟着改：那一份默认是开的（[0054](0054-sync-api-keys.md)），老宿主读成开才与它的默认值一致。两处的注释都写明了这个不对称。

### 四、不写迁移，也不替人打开任何东西

否决「首次升级时把已有的 `dirsEnabled: true` 保留、只改新装的默认值」——这恰好是 `normaliseConfig` 已经做的事：配置里**有**这个键就读它，没有才回落到新的默认值。一个本来就带着目录在同步的人升级之后照旧同步，只是新装的人从关开始。

## 影响

- **正面**：用户报的「每次更换模型都会导致同步」没有了。`agent-default-model` 那一行不再是任何一份的一部分，换模型不改变任何一份的哈希，也就不会触发一次上传，不会多一份留档，不会再出现「服务器覆盖了本机：默认模型」这种通知。
- **正面**：「同步内容」少一行。列表从五份变成四份（`models`、`plugins`、`patch`、`keys`），加上附加目录那一行，比原来短一行；`partDefaults` / `partDefaultsHint` 两个词条从两种语言里删掉。
- **正面**：附加目录的默认值不再是「一个空列表也算参与同步」。新装的人不勾它，就没有一个目录被读过、被封进备份、被写回。
- **负面**：**默认模型从此不再跨机同步**。在 A 机把默认模型换成一个便宜的模型，到 B 机不会跟着变——每台电脑各设各的。这是这条决策的本意，但它确实是一次**能力上的减少**，值得在这里写明。想要这个行为的用户没有替代路径：`patch` 份不再包含它，手工改另一台电脑的 `cordis.patch.yml` 是唯一的办法。
- **负面**：已经升级过一次的人，`agent-default-model` 那一行在一台电脑上被改过、传到另一台上去的那个旧值**不会再被纠正**。两边各自的这一行从此分开演化，谁都不会覆盖谁。旧版本推上去的 `defaults` 字段留在服务器那份备份里没人读，下次推送时随 `Bundle` 一起消失（`push()` 用 `...(merged as Partial<Bundle>)` 拼包，`merged` 里已经没有这个键）。
- **负面**：`dirsEnabled` 的默认值翻转是一次**行为变更**。一个从没用过附加目录、也没有保存过设置的人，在升级前「带 0 个目录」，升级后仍然「带 0 个目录」——行为没变，但卡片上那个复选框从勾着变成空着。一个曾经勾上、保存过的人不受影响（配置里存着 `true`）。
- **验证**：`pnpm typecheck`、`pnpm build`、`pnpm test`（14 个文件 407 条）全绿。改动到的用例：`tests/state.spec.ts`（默认值、`normaliseConfig` 的回落方向、`syncsPart` 少了 `defaults` 一分支、旧配置读成关）、`tests/store.spec.ts`（`collect` 分成三份、`applyPatch` 只认 `models`、默认模型行仍不进 `patch`）、`tests/part-rows.spec.tsx`（「草稿去掉一份」的用例改用 `patch`）、`tests/client-card.spec.ts`（老宿主的 `dirsEnabled` 读成关）、`tests/engine.spec.ts`（`carrying()` 助手：附加目录的用例一律显式写 `dirsEnabled: true`，因为默认值已经反过来；新增「换默认模型不算改动」一条，跑的是用户报的那条路径：改完 `agent-default-model` 行再同步，`pushed` 为假、服务器一个 PUT 都没有、这一行也不被改写）。
