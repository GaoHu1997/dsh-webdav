# 0064 — 卡片上每一条操作产生的提示都带一个「移除」，宿主重算的提示按内容签名收起

状态：`已接受`

## 背景

用户报告两类问题：

1. 「这次同步会这样处理／两边一致，同步不会有任何改动。」这类因某个操作而出现的提示，出现之后没有任何办法手动移走——只能等下一个操作把它覆盖，或刷新页面。逐块排查后确认缺关闭途径的还有：刷新失败红行（`statusStale` + 错误）、「配置文件有改动，重新加载界面后生效」、缺插件提示（`pendingInstall`）、预览块、动作结果句（`message`）、目录读不出的红行、密钥读不出的红行（状态与动作两处）、导出/导入的落盘报告。
2. 插件明明已安装，卡片仍提示「有插件尚未安装」。实证核查（重放 `missingPlugins`、探测实时 `/status`）确认现行判定在本机是正确的，误报出现在两种场景：同步/导入把别的机器声明的插件清单写进本机而 `node_modules` 尚未装齐（提示正确但长期驻留）、以及 `installedPackages` 读不到 `node_modules` 时静默降级成「全部未安装」。无论哪种，用户都没有「我知道了，把它收走」的手段——宿主每次读状态都重算，布尔值原样回来。

约束：`notice` 已有 DISMISS 路由（`sync-state.json` 里的 `notice` 字段可清）；`installOutput` 已有本地关闭（0055）；提示块布局遵循 0061（都在 `.prompts` 一列）。

## 决策

按提示的持有方分两类处理：

**客户端持有的提示——本地清除，不发包。** 预览块、动作结果句（兼作刷新失败红行的状态字段）、刷新生效提示、动作密钥问题、导出/导入报告，各自新增 `closePreview` / `closeMessage` / `closeReload` / `closeKeyProblems` / `closeExportReport` / `closeImportReport` 动作，只 `set()` 清空对应字段。理由：这些提示是这一个浏览器对一次操作的记录，宿主没有对应的状态可清，问它反而制造一次无意义往返。

**宿主每次重算的提示——按内容签名收起，存进宿主状态。** `dismiss` 路由接受 `{ target, signature }`：`target` ∈ `'pending-install' | 'dir-problems' | 'key-problems'`，`signature` 是屏幕上那份载荷的 `JSON.stringify`。宿主把签名写进 `sync-state.json` 新字段 `dismissed`（`Dismissed` 接口，每类提示一个槽位）。`status()` 与 `pendings()` 产出提示后对比签名：一致则不展示；不一致（换了插件名、换了目录、密钥问题变化）则重新出现。收起与 `notice` 一样只在 `stateKey` 匹配本配置时生效。

理由：这三类提示不是「一条消息」而是「当前为真的一个事实」，宿主没有「已读」可记——但用户要隐藏的是**眼前这份内容**，不是这类事实本身。签名恰好表达这个语义：内容没变就一直收着，内容变了就是新事实，重新说话。被否决的备选：(a) 客户端记「不再显示这类提示」——会把真正的新问题也吞掉（装了别的插件、目录真的坏了）；(b) 宿主加「已确认」布尔——下一秒内容变了布尔却不跟着失效，等于把误报固化。序列化用原生 `JSON.stringify`（键序稳定、数组保序），不引依赖、不做规范化：签名只要求和它收起时的形态逐字一致。

**统一的手势。** 每个可移除的提示行右侧放一个 24px ghost 图标按钮（`IconCloseOutlineRegular`，即标题行刷新按钮的形状），`aria-label` 与 Tooltip 共用新增的 `promptDismiss` 文案；卡片与手动备份面板各持一份同形组件。文字按钮会给临时消息赋予操作的视觉分量，✕ 不需要词语。

**顺带的协议加固。** 排查测试期 unhandled rejection 时发现 `requestStatus` 是唯一不校验载荷形状的请求——宿主版本错位时 `adopt()` 会在 `view.config.url` 上崩溃。补上与 `requestExport`/`requestImport` 同口径的检查：载荷缺 `config` 时按协议错误返回消息，不再抛错。

## 影响

- 正面：用户对屏幕上每一条因操作出现的提示都有了明确的移除手段；「已安装仍提示未安装」的正确性顽疾（无论来自清单先行还是 `node_modules` 缺失）可以由用户自行收起；收起不是永久静音——事实变化后卡片照常说话。
- 正面：状态接口不再因版本错位崩溃成 unhandled rejection。
- 代价：`sync-state.json` 多一个 `dismissed` 字段（每槽位一个签名字符串，通常为空）；旧宿主收到带 `target` 的 dismiss body 会按现有 400 路径报错，前端与宿主需同版本发布（本仓库一直如此）。
- 代价：签名是内容敏感的——同样的目录问题如果 `message` 文本变了（宿主措辞调整），签名失配会重新展示一次，属于可接受的自愈行为而非错误。
- 布局：提示行从纯 `<p>` 变为 `.promptRow` flex 行；预览标题进 `.outputHead` 行。DOM 测试同步更新。
