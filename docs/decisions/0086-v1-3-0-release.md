# 0086 — v1.3.0 发布：手动同步不再后台轮询

- 状态：已接受
- 日期：2026-11-03

## 背景

`v1.2.9` 之后的未发布变更把「手动同步」改为真正的静默状态：宿主不再周期性重读配置以寻找自动间隔，卡片也不再在手动模式下轮询状态。与此同时，「关闭同步」从自动间隔选项移回同步动作行。用户明确要求将这些变更作为 v1.3.0 发布，并要求 npm 包中带有易读的更新说明。

仓库的既有发布约定（[0032](0032-tag-driven-release.md)）要求版本号独立以 `chore` 提交，推送与 `package.json` 版本严格一致的 tag 才触发 npm 发布与 GitHub Release。npm 产物的 `files` 白名单包含 `README.md`，不包含被 gitignore 的 `docs/`，因此只有写进 README 的发布说明才会随 npm 包交付。

## 决策

- 将 `package.json` 的版本升至 `1.3.0`，作为独立的 `chore` 发布提交；不改动 lockfile 中与依赖解析无关的内容。
- 将 v1.3.0 的用户可见更新说明写在 README 的安装信息旁，保证同一份说明既能在 GitHub 仓库阅读，也会进入 npm tarball：手动模式不排后台定时器、不做周期状态轮询；保存自动间隔后立即重排，且旧的运行任务不能复活已取消的 timer；「关闭同步」作为动作按钮并保留立即停同步的能力。
- 运行仓库 CI 同等检查（typecheck、tests、build:all）及 pack 验证；通过后提交并推送 `main`，再推 `v1.3.0` tag。仍由既有 tag 工作流完成 npm publish、GitHub Release 与 tarball 附件，不在本机直接发布。

未选择只依赖 GitHub 自动生成的 Release notes：这不会成为 npm 包的 README 内容，且既有 workflow 生成的摘要不足以说明用户行为变化。

## 影响

正面：npm 包自身包含版本号与本版本更新内容，用户安装后可在包 README 中看到行为变化；发布仍由单一 tag 驱动，npm 包、GitHub Release 和 tag 共用同一版本号。负面与代价：版本说明需要在每次发布时同步维护；新增 README 与决策索引更新，但不改变运行时代码、备份格式或同步协议。若 CI、tag 推送或 npm 发布凭据失败，应停止在已知状态并报告，不能绕过验证或手动改发其他版本。
