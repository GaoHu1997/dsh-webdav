# 0084 附加目录也能选单个文件：path 既可以是目录，也可以是文件

- 状态：已接受
- 日期：2026-11-03

## 背景

用户 2026-11-03 的原话：「我需要可以选文件，也可以选目录，选文件就只同步问价(文件)，选目录就同步目录下所有(文件)」。

[0036](0036-extra-directories-part.md) 的「附加目录」只认目录：`readDirs` 走 `readTree`，写回时按 `path` 建目录。但用户想带着走的东西里，有单个文件（一个 `think.json`、一个插件自己的索引），而不是它们所在的整个文件夹；把文件夹整个带走，等于把同目录下别人的东西一起塞进备份。

难点不在读文件，而在**旧版本会怎么处理它不认识的行**。`dirs` 这一份是整份合并、较新的那份胜出，所以一台还停在 1.2.8 的电脑完全可能收到一条「文件」行。那一版把每一行都当目录：拿 `dir.path` 当根，再按 `files[].path` 在它下面写。若文件行把名字塞进 `files[0]`（`{path: 'think.json', data}` 那样的相对名），1.2.8 会**在文件自己的名字下面造一个目录**，把内容写进去 —— 一个没人要、事后也说不清的目录。这一条决定了数据形状。

## 决策

**一条路径行仍然是「一个路径 + 它里面的东西」，但多一个 `kind` 和一份自带字节**（`src/wire.ts`）：

```ts
export interface DirSpec {
  path: string                 // 绝对路径，或 ~ 开头；原样带走
  kind?: 'dir' | 'file'        // 不写读作 'dir'：旧版本写出的行都是目录
  data?: string                // kind === 'file' 时这一个文件的字节（base64）
  files: DirFileSpec[]         // kind === 'dir' 时目录里的文件，'/'-分隔相对路径
}
```

文件行的 `files` **保持空数组**。1.2.8 不认识 `data`，也不认识 `kind`，它看到的就是一条 `{path, files: []}` 的行，于是**什么都不写**（那一版的 `writeDirs` 只遍历 `files`）。这不是碰巧：把「文件内容藏在 `files` 里」的写法在旧版本上会造出上面那个目录，而空 `files` 的代价只是「旧电脑不恢复这个文件」，文件在服务器上原样留着，等它升级。反过来，旧电脑读到这一行只读不写时，`dirs` 整份合并会让这条来自新电脑的行原样留下。

**类型由 `stat` 当场决定，配置不记。** `sync.json` 里的 `dirs` 仍是 `string[]`，没变成 `{path, kind}`：给用户多一个要维护的字段，而这个字段系统本来就能看出来。路径指向什么，`readDirs` 用一次 `stat` 就知道了；同一个路径在另一台电脑上是目录还是文件，也与这台电脑无关 —— 它按自己的盘解析自己的那一份。

**读**（`src/dirs.ts`）：`stat` 说是文件，就只读这一个文件（同样受 8 MiB 上限，超了整条不同步并报出来），`entries` 里放 `{path, kind: 'file', data, files: []}`；既不是目录也不是文件（管道、设备）报「这个路径既不是目录也不是文件，读不了」；不存在的消息改成「这台电脑上还没有这个目录或文件」。**只读单个文件时不受 `node_modules` / `.git` 跳过表影响** —— 跳过表是给目录遍历用的，用户明确点名的那个文件就该被带走。

**写**（`writeDirs` / `dirsDiffer`）：文件行只写它自己的那个路径（父目录不存在就建），不与 `files` 混用；`data` 不是字符串的文件行**不做任何事**，绝不退化成「在这条路径下建目录」。`dirsDiffer` 用同一套判断，只有字节真的不同才 `keepBefore`。

**整份还是整份**：`DIRS_MAX = 5` 数的是行数，目录行与文件行共用这一个列表、这一个上限（用户在卡片上看到的是同一列路径）。形状校验（`openRemote` 那一处）把「没有 `data` 的文件行」当作**本插件没写出过的形状**报出来并点名 `dirs`，与其余四份一致，而不是猜一个意思。

**卡片上多一个「选择文件」**（`src/client/WebdavSyncCard.tsx`、`card-store.ts`、`picker.ts`）：

- 宿主**没有**选文件的对话框：整个安装里只有一处 `showOpenDialog`，`properties` 是 `["openDirectory", "createDirectory"]`，`__DSH_DIRECTORY_PICKER__` 也只暴露 `pick()`。为这一点去改宿主不在本插件范围里。
- 宿主却有一条**能把浏览器里的 `File` 换成本机路径**的桥：桌面端 preload 暴露
  `__DSH_HOST_PATHS__.pathFor(file)` → `electron.webUtils.getPathForFile(file)`。于是卡片用一个隐藏的 `<input type="file">` 打开系统选文件框，选中之后向这座桥要路径，拿到的就是真路径（不是上传一份副本）。
- 网页端没有这座桥时，`fileChooser()` 让选文件失败，卡片与 `选择目录` 遇到对话框不可用时一样**留一个空行手打路径**。同一个列表里两种行只是入口不同，落地都还是「一个路径」。
- 配置里选的是文件还是目录，卡片不标注：它不读盘，路径本身已经说明一切；读不出来时由状态里的 `dirProblems` 按路径报「哪一条、为什么」。

被否决的备选：

- **配置改成 `{path, kind}`**。多一个必须两边维护、且可能被手改错的字段；`stat` 已经能给出答案，而两台电脑各自的盘本来就不必一致。
- **文件字节放进 `files[0]`（相对名 = 文件名）**。见背景：1.2.8 会在文件自己的名字下造目录写内容。形状上的“复用”换来旧机器上的一个垃圾目录，不值得。
- **另开一份 `files` 份、或同一行里再加一个文件列表**。第五份的存在理由就是「路径跟着配置走」，再分一份就有两套上限、两套状态与两处 UI，而它们要解决的问题完全相同。
- **让卡片自带一个文件浏览器**（列出目录、点进去选文件）。要重写一套列表、权限与路径拼接，宿主已有目录浏览服务但不在卡片上下文里；隐藏的 `<input type="file">` 加桥是两行的事。
- **走 `dsh-client-file-upload` 上传字节**。那是把浏览器里的副本交给宿主，同步要的是本机原文件，路径才是身份。

## 影响

正面：

- 需求两半都成立：选目录带走整棵树，选文件只带走那一个文件；恢复写回同一个路径。
- 旧版本电脑上的最坏结果是「这一条暂时不恢复」，而不是多出一个目录；文件始终在服务器上。
- 配置形状没变，旧 `sync.json` 直接可用；`~` 前缀对文件行同样生效（[0079](0079-home-relative-extra-directories.md)），插件自己的单文件数据可以按 `~/xxx.json` 跨机器同步。
- 目录里的 JSON 文件贡献凭据引用这条规则（[0079](0079-home-relative-extra-directories.md)）对文件行同样适用：单文件里的 `ref` 与目录里的文件走同一个 helper。

负面：

- **旧版本不认识文件行**：1.2.8 只把它原样带着，既不同步也不恢复，卡片上看起来像一条「读不出来」的路径（其实读得出来，只是它不写）。要等它升级。
- **多一个形状要校验**：`kind` 只有两个值、文件行必须带 `data`；手改过的备份会被整份拒绝，需要「用本机覆盖服务器」。
- **上限对单文件更紧**：8 MiB 对一个文件是硬上限，超了整条不同步；`2000` 个文件的上限对文件行没有意义（不显示，也不提示）。
- **网页端只能手打路径**：没有桥就没有选文件框，用户得自己知道文件在哪。
- **卡片不告诉你这一行是文件还是目录**：路径列表上看不出来；写出错时只能从错误消息反推。
- 同一个列表混两种行，`选择目录` 与 `选择文件` 两个按钮在 5 条上限处一起变灰 —— 与「这条路径是什么」无关。
