# 0042 — 转发区只给一个地址框：去掉整段说明、复选框与标题同字号、端口收进地址

- 状态：`已接受`
- 日期：2026-10-20
- 相关：[0041](0041-relay-reuses-sync-config.md)（转发复用同步配置：开关、同一个保存、本地 Basic 账号；本条只改外观与复制方式，不改授权、端口持久化或账号生成规则）、[0037](0037-headers-field-shows-two-lines.md)（同样是「说明从字段旁撤掉」的一类改动）、[0031](0031-card-layout-and-chinese-messages.md)（卡片分区与排版口径）

## 背景

0041 实现之后，转发区在卡片上长成三行：一段解释「它是干什么的、为什么没有第二份配置」的小字，一个 14px 的复选框，一个地址值加一个端口值再加一串标签，账号两行各带一个复制按钮。实际用起来的三个问题：

1. **那段说明是重复的。** 它讲的三件事——转发的就是上面这份配置、没有第二份要填、没有第二个保存——在卡片上已经由布局本身说完了（转发区就在服务器表单里、整张卡片只有一个保存）。一段要先读才知道「其实不用读」的小字，只把用户的视线从开关上推开。
2. **复选框比小标题还大。** `Checkbox` 原语是 14px，而这一区的标题 `.legend` 是 12px、其余字段标签也是 12px。一个开关压在自己的标题上，看上去像页面里另一个层级的东西。
3. **地址与端口分开列，反而多出三个复制按钮。** 客户端要填的是一个 WebDAV 地址，端口只是地址的一部分（`http://127.0.0.1:3426/dav`）。把端口单列成一行、给地址、用户名、密码各配一个复制按钮，等于要求用户分三次复制同一件事；而实际上只有地址值得点一下复制，账号是两个短串，读着敲就行。

## 决策

### 一、删掉转发区那段解释文字

`relayHint` 这个键整个删掉（中英文两本字典都不再有它），转发区从标题直接进复选框。解释性文字只保留两种情况下的句子：地址还没填（`relayNoTarget`）与账号还没生成（`relayAccountLater`）。删掉的是「为什么这样设计」，留下的是「现在缺什么」。

被否决的备选：把它折叠进 Tooltip 或折叠面板。那只是把同一段话藏起来，仍然要一次点击才能确认「不用再填一份」；而布局已经回答了这个问题。

### 二、复选框与区标题同字号

`.relaySwitch label` 固定 `font-size: 12px; line-height: 18px`，与 `.legend`、`.fieldLabel`、`.relayLabel` 一致。复选框本身就是「同步内容」里那几行用的同一个原语，同一张卡片里同一个控件不应该有两种字号。原语的 14px 不动：它是别处的默认，改动它会影响整张卡片的所有复选框。

### 三、地址是一个只读文本框，端口只在地址里

> **本节已被 [0043](0043-relay-address-text-and-sync-text-button.md) 取代**：地址改成等宽 `<code>` 纯文本 + 紧跟其后的复制图标按钮（含复制成功/失败反馈）。本节其余部分——端口只出现在地址里、只在监听出错时才给「换一个端口」、账号不给复制按钮——仍然有效。

转发区只剩一个 `<input readonly>`，占满整行，等宽字体，边框与背景沿用卡片自己的字段样式（`.relayAddress`），旁边一个**复制**按钮。端口不再单独显示，也不再单独可改。

- **为什么不用只读的纯文本**：地址是要被选中的，输入框自带的选中、全选与剪贴板语义比一个 `<span>` 更可靠，也允许用户不用按钮直接复制。
- **为什么端口不再单独列**：客户端要填的是地址，端口只是它的一段。单列一行会让用户以为这是两件事要分别确认。
- **端口怎么改**：正常路径下不需要改。只有当宿主报告监听失败（端口被占用等）时，错误旁边才出现**换一个端口**（`relayNextPort`，仍是 `card-store` 里那个 `+1`、封顶 65535 的 `nextPort()`），改完仍然走整张卡片唯一的**保存**。没有错误就不显示这个按钮：一个平时看不见的操作，比一个平时摆在眼前、九成时候不该点的按钮更不容易被误点。
- 端口本身的持久化、默认 `3426`、不自动换端口这些规则不变（仍按 0041 第二节）。

被否决的备选：把地址框做成可编辑、编辑后反解出端口。那等于给用户一个「改地址就等于改配置」的隐式入口，地址与上游 `url` 的关系会变得需要解释；而端口是唯一可编的部分，没有必要为此开放整个字符串。

### 四、账号在地址下面并排显示，不再各带复制按钮

用户名与密码以 `relayLabel` + `relayValue` 的形式并排一行（`.relayAccountRow`），与字段标签同字号，等宽字体。没有复制按钮：两个短串是读着敲进另一个客户端的，多两个按钮只会让「复制」这件事看起来适用于全部三行。

被否决的备选：一个「复制账号密码」把两行一起写进剪贴板。那需要约定 `user\npassword` 还是 `user:password`，而不同客户端的粘贴行为不同，约定本身就要再解释一句——正好是本节要删掉的那类文字。

## 影响

- **正面**：转发区从三行文字加七个控件降到一个开关、一个地址框、一个复制按钮、一行账号；地址的复制路径唯一。
- **正面**：复选框与标题同字号后，转发区读起来是「同步内容」的又一行，而不是卡片里另起的一个层级。
- **正面**：删掉 `relayHint`、`relayAddressLabel`、`relayPortLabel`、`relayAccountHint` 四个键，两本字典各少 4 条；`RelayPanel` 不再有「哪个值刚被复制」的分支状态（0043 又把这一支加了回来：地址旁的复制图标会短暂变成对勾，复制失败还会说一句）。
- **负面**：端口的当前值不再直接显示，用户只能从地址里读。端口冲突的错误信息本身带端口号（`转发端口 3426 用不了：…`），需要时仍能看见。
- **负面**：账号不能一键整组复制，得分别读或手动选中。这是有意的取舍，不是遗漏。
- **验证**：`pnpm run typecheck` 通过；`pnpm exec vitest run` 12 个文件、360 例全部通过（`tests/relay-panel.spec.tsx` 从 5 例增到 6 例：新增「没有错误时不显示换端口」）。
