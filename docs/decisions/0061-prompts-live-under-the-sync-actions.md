# 0061 — 动作提示归到「同步内容」底部，紧跟在动作行下面

- 状态：已接受
- 日期：2026-10-21
- 相关：[0031](0031-card-layout-and-chinese-messages.md)（卡片按「设置 / 动作」重排）、[0039](0039-the-card-says-check-and-sync-apart.md)（两个时间戳）、[0055](0055-closable-install-report.md)（安装报告自带关闭）、[0060](0060-manual-backup.md)（手动备份是「同步内容」下面的一节）

## 背景

卡片是三轮重排的产物（0031 决策五把保存挪到最外层，0060 又在「同步内容」下面接了一节「手动备份」），而「一次动作说完的话」一直留在旧位置上：宿主提示、需要重载、缺插件、安装日志、同步预览、结果句子、确认框、正在工作——这一串排在 `<ManualBackupPanel>` **之后**，也就是卡片的尾部。

用户点「预览」或「服务器覆盖本机」之后看到的是这个形态：这次同步会这样处理写在**手动备份**的下面。产生它的那一排按钮在它上面隔了整整一节，按钮已经滚出视口，读起来像是「手动备份」这一节自己的一个常驻说明——而它随时会变成别的内容（预览换成确认框、确认框换成结果句）。用户要求它「在 同步内容底部、手动备份上面」。

这与 0060 里「手动备份是『同步内容』下面的一节」那条并不冲突：那一条说的是手动备份相对同步内容的位置，这一节要修的是**提示**的位置。两者一起读，顺序正好是：同步内容（设置 + 动作 + 这些动作说的话）→ 手动备份。

约束：`preview` 不是常驻设置，它跟着动作来（`card-store.ts` 里 `preview()` 写入、`sync()`/`undo()`/`answer(yes)` 清掉、`reset()` 也清掉），所以它不该占一个带 `border-top` 的 `<section>`——那正是让它看起来像常驻设置的原因。

## 决策

- **整串提示移进「同步内容」小节，紧接在 `.footer` 那一排动作之后，并用一个 `<div className={css.prompts}>` 收成一列**。成员与先后次序一字未改：宿主提示 → 需要重载 → 缺插件 → 安装日志 → 同步预览 → 结果句子 → 确认框 → 正在工作。次序原本是对的（先说宿主发现了什么，再说还要做什么，再说这一次的预览，最后才是那句结论与那个必须回答的问题），搬位置不动次序。
- **`.prompts` 是一列，`gap: 10px`、`margin-top: 6px`**（`src/client/WebdavSyncCard.module.css`）。收成一列而不是让每个块自带 `margin-top`，是因为同时在场的有几种：只在预览时是一个，只在装包时是三个，同时在场就五个；让间距来自容器，两个块和五个块的间距就是同一个数，不会因为谁在场而变。没有一个块在场时这一列是空的，整体塌掉，下一节的 `border-top` 照旧。
- **预览从 `<section className={css.section}><h4 className={css.legend}>` 降级成 `<div className={css.previewBlock}><h5 className={css.previewTitle}>`**。它是八块里唯一自带名字的一块（`previewTitle`「这次同步会这样处理」），给一个 12px/600 的 `.legend` 会让它与小节标题同级，读起来像第四章；`.previewBlock` 沿用 `.confirm` 的形态（`10px 12px` 内边距、`--dsw-alias-border-l4` 描边、10px 圆角），标题 12px/600 落在宿主覆盖块（`.section .previewTitle`）上调到 13px，与这一节里其它小标题下的第一行（`.backupTitle`、`.partHint`）一致，同时仍然比 15px 的小节标题低一档。
- **否决的备选**：(a) 只把预览搬上来，其余七块留在原处——那七块同样是动作的回答（确认框尤其明显，它是「服务器覆盖本机」按下去之后弹的东西），搬一块留七块等于把一个说不清的理由分成两种位置；(b) 把提示做成浮层或抽屉——卡片在设置页里滚动，浮层会盖住下面正在讲的内容，而「确认覆盖本机」这种问题本来就需要用户拿卡片上的份名与状态去判断；(c) 保留预览的 `<section>` 与 `border-top`，只改顺序——它于是成为「同步内容」小节里唯一带自己一条分隔线的块，而内容只有几行，那条线读起来比内容还重；(d) 让每块自己带 `margin-top`——间距会随在场块数漂移，见上。

## 影响

- 「同步内容」这一节现在是自足的：设置（复选框与状态）→ 时间戳 → 动作行 → 这一节说的所有话；往下读到的「手动备份」不再被一段会变的话插在中间（0060 的两行结构未变，`tests/manual-backup-panel.spec.tsx` 仍按原样通过）。
- 提示离产生它的按钮近了，代价是「同步内容」小节会随提示变高——预览出现时按钮行下面多出几行。这正是用户要的：一次预览的答案紧跟着问它的动作，而不是要越过下一节再回来找。
- 没有为这处位置调整补测试：仓库里没有任何测试断言预览或提示的 DOM 位置（`tests/client-card.spec.ts` 只断言 `card.getSnapshot().preview` 这个状态），布局的回归仍靠人工核对，与 0031 决策七记下的口径一致。
- 「同步内容」小节内的块间距现在由 `.prompts` 一处决定：以后再加一种动作提示，只要放进这个 `div`，就自动拿到同样的间距与同样的位置，不需要各自决定离上一块多远。
- 逻辑没有任何变化：八个块读的是同一批 `card-store.ts` 的字段，条件与文案一字未动，宿主侧与路由完全不受影响。
