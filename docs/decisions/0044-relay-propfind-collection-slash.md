# 0044 — PROPFIND 基目录时补上规范尾斜杠

- 状态：`已接受`
- 日期：2026-10-20
- 相关：[0041](0041-relay-reuses-sync-config.md)（本机 WebDAV 转发）、[0012](0012-address-path-and-double-slash.md)（基路径规范化）

## 背景

转发地址保留上游基路径，例如 `https://dav.example.com/dav/` 对应本机 `http://127.0.0.1:3426/dav`。客户端会把地址路径直接作为资源路径进行 WebDAV 探测；有些客户端对地址本身发送 `PROPFIND /dav`。转发器原样把它映射为上游 `/dav`，但部分 WebDAV 服务只将 `/dav/` 识别为集合目录，并可能对无尾斜杠形式返回 403。插件自身探测目录时会使用尾斜杠，所以这类差异只会在其他客户端使用转发地址时暴露。

## 决策

当请求方法为 `PROPFIND` 且映射后的路径恰好等于目标基路径时，在转发给上游前为该集合路径补上一个尾斜杠。子资源路径不变；`OPTIONS`、`GET`、写入等其他方法不做改写；查询串与请求体保持原样。

不对所有路径或方法一概补斜杠，因为 `/dav` 也可能被客户端当作非集合资源使用，且转发器承诺保留普通请求的语义。也不通过重定向处理，因为 WebDAV 客户端对重定向的跟随及认证转发行为并不一致。

## 影响

- **正面**：对基目录做集合探测的客户端能够兼容要求规范集合路径 `/dav/` 的服务器，不必手工修改转发地址。
- **正面**：变更范围只限于针对基目录的 `PROPFIND`，不会影响文件路径、其他 HTTP 方法、查询串或请求体。
- **负面**：收到的基目录 `PROPFIND` 上游路径与客户端原始路径会有一个有意的尾斜杠差异；依赖无斜杠路径有特殊语义的服务器不适用于该场景。
- **验证**：回归测试覆盖基目录探测、`OPTIONS` 不变以及子资源 `PROPFIND` 不变。
