# 0045 — 转发的三个值各带一个复制图标，图标紧贴它复制的那段文字

- 状态：`已接受`
- 日期：2026-10-20
- 相关：[0043](0043-relay-address-text-and-sync-text-button.md)（本条调整它第一节：地址旁的复制图标不再被推到行尾，标签也从「复制」改成三个各自说明对象的键）、[0042](0042-relay-section-one-address-box.md)（本条推翻它第四节「账号不给复制按钮」；它关于端口收进地址、只在监听出错时才给「换一个端口」的决策仍然有效）、[0041](0041-relay-reuses-sync-config.md)（转发复用同步配置，授权、保存与账号生成规则不变）

## 背景

0043 之后转发区是「一行地址 + 紧跟一个复制图标」，下面是并排的用户名与密码两个值。实机用下来报了两件事：

1. **复制图标离地址太远。** `.relayAddress` 是 `flex: 1`，地址文字只占自身宽度，剩下的空白全归它，图标于是被推到整行的右端。窄卡片上还勉强，宽卡片上图标和它复制的那个字符串之间隔着半屏空白，看起来像两个不相关的东西。
2. **账号的两个值也要能复制。** 用户名是 `dsh` 加一串十六进制（如 `dshd0bd`），密码是 32 位十六进制，照着卡片往另一个客户端里敲很容易出错；用户明确要求它们各带一个复制图标。

## 决策

### 一、复制图标紧跟它复制的值，不再占满剩余宽度

`.relayAddress` 的 `flex: 1` 改成 `flex: 0 1 auto`（保留 `min-width: 0`），地址行因此变成「文字 + 图标」紧挨着的一对，左边贴齐；地址太长时仍在原位换行（`overflow-wrap: anywhere` 不变），不会把图标挤到下一行。

- **为什么不是把图标放到值的前面**：三个图标统一读作「复制我左边这一串」，与账号行的排法一致；放前面就得逐个说明它复制的是右边还是左边。
- **被否决的备选**：保留 `flex: 1`、给 `.relayCopy` 加 `margin-left: auto` 之类把图标钉在行尾。那正是这次要修的样子。
- **被否决的备选**：给地址行加 `justify-content: space-between`。结果与现状相同，只是换了个说法把图标推远。

### 二、账号的两个值各带一个复制图标，标签改成三个各自说明对象的键

`.relayAccountRow` 里「用户名 + 值 + 图标」「密码 + 值 + 图标」各包成一个 `.relayPair`（`inline-flex`，内部间距 6px，两对之间 14px），窄卡片换行时也只会整对换行，不会把图标与它复制的值拆开。

- **三个键替代原来的一个**：删掉通用的 `relayCopy`（「复制」），新增 `relayCopyAddress` / `relayCopyUser` / `relayCopyPassword`（「复制地址」/「复制用户名」/「复制密码」）。三个图标同名的话，屏幕阅读器读到的就是三个分不出对象的「复制」；复制成功时那一个图标换成对勾、Tooltip 与 `aria-label` 临时变成共用的 `relayCopied`（「已复制」）—— 它就在刚点过的那一个位置上，说的是哪个值由位置说明。
- **复制状态带上对象**：`Copied` 从 `boolean | undefined` 改成 `{ target: 'address' | 'user' | 'password'; ok: boolean } | undefined`，只有刚被点的那一个图标会变成 `IconCheckOutlineRegular`，一秒后（`COPIED_MS = 1_000`）变回；失败时同样只有那一个旁边显示 `relayCopyFailed`（`role="alert"`）。定时器仍在卸载时清掉，改点另一个值时先清掉上一个。
- **推翻 0042 第四节**「账号是两个短串，读着敲就行」。实机用下来，32 位十六进制照着敲确实会错；而复制一个本地生成的账号不会泄漏上游凭据 —— 它本来就是为了填进另一个客户端才生成并明文显示的。
- **被否决的备选**：一个「复制账号密码」按钮把两行一起写进剪贴板。0042 已经否决过：`user\\npassword` 还是 `user:password` 各家客户端粘贴行为不同，约定本身就要再解释一句。
- **被否决的备选**：把用户名与密码合成一行 `user:password` 只配一个图标。Basic 客户端要的是两个字段，合成一行反而要求用户再拆开。

## 影响

- **正面**：三个值都有一键复制，且标签各自说得清复制的是什么；图标贴着值，读起来是一对，不再是行尾一个孤立的图标。
- **正面**：窄卡片上换行只发生在「对」与「对」之间，图标不会和它的值分开。
- **负面**：`RelayPanel` 里的复制状态从一个布尔变成带 `target` 的对象，判定的分支比 0043 那一版多一处。
- **负面**：字典净增两条（三个专用键换掉一个通用键），两本字典都要同步维护。
- **负面**：地址行的排法依赖 `.relayAddress` 不重新被撑开；将来若有人给它加回 `flex: 1`，图标会重新跑到右边，而现有测试只读静态标记，拦不住这一类回归。
- **验证**：`pnpm run typecheck`（`tsc -p tsconfig.client.json --noEmit`）通过；`pnpm test` 全部通过（`tests/relay-panel.spec.tsx` 断言三个 `aria-label`、地址与图标同在一行、账号两个值的图标各就其位）。README 的卡片说明、浏览器半边一节与「开启与复制」三步同步更新。
