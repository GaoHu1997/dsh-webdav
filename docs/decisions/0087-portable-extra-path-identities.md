# 0087 附加目录与单文件采用可移植路径身份

- 状态：已接受
- 日期：2026-11-04

## 背景

附加目录与单文件共用 `dirs: string[]`。过去，选择器给出的本机绝对路径直接进入配置和备份：例如一台 Windows 机器上的 `C:/Users/alice/.dsh/notes` 到另一台机器仍是这个字符串。用户名、操作系统或 DSH 主目录不同，就无法指向接收机上同一份 DSH 数据。只把卡片显示缩短为 `~/notes` 并不能修复身份、去重和写回；用户还会以为已经能跨机器复用。

[0079](0079-home-relative-extra-directories.md) 已经允许 `~` 开头的路径按各机 DSH 主目录解析，但选择器、本机旧配置、远端旧备份与合并中的路径身份仍需要统一。[0084](0084-single-file-extra-path.md) 的单文件形状必须保持：`kind: 'file'` 自带 `data`、`files: []`，旧版本读到不认识的文件行也不会在文件名下面造出一个目录。

这次改动要解决 DSH 主目录内的路径可移植性，不是替任意外部目录建立跨机器映射。旧备份没有发送机主目录元数据；在这个前提下推断任意自定义根会写错地方，而不是帮助用户。

## 决策

### 1. 路径身份与本机写回位置分开

使用共享的、浏览器安全的路径纯函数统一选择器、配置读取、状态展示、备份条目与核心处理中的身份。`portableDirPath(value: string, home?: string): string` 只把**实际 DSH 主目录内**的绝对路径转换为 `~` 或 `~/后缀`，并统一安全的 `~` 分隔符与 `.` / `..`；外部绝对路径保留原样。

实际主目录来自宿主 `paths.homeDir`。判断按规范化后的目录段与严格边界进行，不是替换一个字符串前缀：主目录为 `C:/Users/alice/.dsh` 时，`C:/Users/alice/.dsh-other/notes` 不属于它。Windows 路径的根和主目录段比较忽略大小写，兼容盘符、目录大小写与分隔符；不能把不同根或不同系统的外部路径猜成同一位置。

**`~` 始终表示每台机器实际的 `DSH_HOME`，不是 OS 用户主目录。** 自定义 DSH 根目录同样遵守这一语义。`~/notes` 到每台机器都在其 DSH 主目录下解析；不引入任意 `~user` 或其他用户主目录 token。接收机解析这个身份之后才决定本机读写路径。

### 2. 选择器与旧本机配置也必须产生这一身份

- 选目录、选单个文件都在加入卡片列表时立即转换主目录内的路径，不只是缩短显示。新增项与已有项都按 canonical 身份比较，避免绝对路径、`~/…`、反斜杠或安全 dot 变体形成重复行。
- 从已有本机配置读取时，已知实际主目录内的旧绝对路径迁移为可移植身份；状态接收也采用同一个转换，因此旧宿主状态仍能正确展示。
- 手打路径的 `editDir` 保留原始文本，不在每个字符输入时重写路径或关闭输入行。身份规范化在采用已保存状态、选择器加入与核心处理这些边界完成。
- 状态协议仅补可选 `PathsView.homeDir?: string`；主目录未知时不虚构值。客户端复用既有 status 数据，不增加 RPC，也不改变保存后读取状态的请求顺序。

### 3. 旧远端只识别有限的默认 DSH 主目录格式

旧备份没有发送机的实际主目录信息，除与本机已知实际主目录直接匹配的路径外，只识别以下默认 DSH 根目录格式及其后缀：

- Windows：`drive:/Users/<account>/.dsh`，其中 `drive` 为实际盘符。
- Linux：`/home/<account>/.dsh`。
- macOS：`/Users/<account>/.dsh`。
- root：`/root/.dsh`。

这几种格式可转换为 `~` / `~/…`，让旧机器用户名下的 DSH 数据与接收机的同一身份汇合。未知自定义根、UNC 外部位置及其他绝对路径不按用户名或文件名猜测，继续按原路兼容。

卡片对启用的附加同步中每条非空、非 home-relative 路径明确提示：**保留绝对路径，不能自动映射；跨机器同步必须每台机器都有同一路径。** 提示保留完整路径，复用现有问题样式；空输入行、可移植路径与已关闭的附加同步不会产生这种警告。

### 4. 保留失败语义、安全边界与文件形状

- 不可读的目录或单文件不等于空内容；保留服务器副本，继续报告哪条路径读不成。不知道实际 DSH 主目录时，home-relative 条目也让服务器副本穿过，不盲写到猜测的位置。
- 保持「只增不减」：同步可以写入或覆盖，但不会因为移除路径、关闭开关、读取失败或迁移身份删除文件。
- `~/../` 越出主目录、NUL、portable 后缀里的盘符或驱动限定路径都不能成为有效目标。目录内部文件仍受相对路径边界检查，不能通过 `..`、绝对前缀、反斜杠或盘符写出目录根。
- 保持 `dirs: string[]`、`DIRS_MAX = 5` 和单文件的 `kind: 'file'` / `data` / `files: []` 字节载荷；`BUNDLE_VERSION = 1` 不变。新选中的外部绝对路径若会被默认根识别器误判，行内可选 `pathMode: 'absolute'` 明确保留固定地址。只要载荷含此标记，信封使用受 AAD 认证的 v2；普通载荷继续用 v1，新版本读取两者。已发布的 v1 客户端不能读取 v2，因此会拒绝而不是重写并丢弃该标记；不能依赖未知字段能穿过旧版本。标记不用于猜测旧备份发送机的主目录。
- 真实内容变更仍用整份三方合并及新者优先；路径表示变化先以证据校准临时比较基线，不能制造「两边都改了」。同步和预览共享比较逻辑；旧缓存必须先通过密文校验和、解密及字段检查，再分别以整份 `dirs` 原始或规范化哈希精确匹配本机、服务器各自的旧基线。缓存总校验和通过不代表它仍是分片基线，两个匹配不能互相代替。
- 新的本机状态以 `ScopedPartHashes.dirsHome` 记录该目录哈希已经在哪个实际 DSH 主目录下按规范身份测量；标记与哈希一起参与 blind 回滚，且不进备份载荷。临时比较用规范化的服务器内容，上传判定和持久服务器基线仍用原始服务器哈希，需要迁移的身份通过普通差异重写一次，不伪装成损坏备份。
- 缺少证据且双方都变化、规范内容又不同时，停止本次同步并提示先导出本机备份再明确选择服务器恢复；不清空旧哈希，不以 mtime 推断「只是路径变了」。新增固定外部地址也不能用旧缓存的默认根推断来证明本机未改。
- 停用、没有选中路径，或任一本机条目不可读（不含仅缺失、可恢复创建的目标）时，附加分片整份暂缓，携带远端原始行，不做不相关的别名归并。部分条目仍可读也不上传半份数据，不更新附加分片基线，并使后续恢复可用时重新取得完整服务器内容；其他 profile 分片可以继续同步。不知道主目录且有 `~` 条目时同样暂缓，不虚报目录已应用。
- 恢复、手动导入和撤销在任何目录文件访问及旧插件配置提取之前统一迁移身份。跳过集合来自本机选择，只用已知本机主目录解析；按实际 native 目标比较，Windows 忽略别名大小写，不可读根的后代及较宽目录行里覆盖同一文件的条目也跳过。仅缺失的目标则可恢复；携带内容相同时也在本次补回缺失文件，而不是先记录哈希等下一次。
- 多个旧身份汇合时，同内容文件去重、目录中不相交的文件合并；同名不同字节或目录与文件类型冲突则报错停止覆盖，不静默丢弃任何一份。POSIX 绝对文件名中的真实反斜杠保持原义，不转换为目录层级。

### 被否决的备选

- **只把 UI 文案或显示改为 `~/…`。** 底层仍是发送机绝对路径，去重、远端匹配与接收机写回都不会因此可移植。
- **把 `~` 当系统用户 home，或加入任意用户 home token。** DSH 可以使用自定义根目录，这会改变既有 `~` 的契约，并把 DSH 数据写到错误位置。
- **按任何用户名片段或常见后缀推测外部路径。** 没有发送机元数据，不知道哪个根才是 DSH 主目录；未知路径必须保留并提示限制，而不是静默映射。
- **为每个目录和单文件新增 RPC 查询主目录。** 同一个状态已能携带实际主目录，额外请求没有必要，还会改变客户端的既有请求顺序。
- **改变单文件字节载荷或让旧版把文件误当目录。** 此问题是路径身份；可选地址标记不改变 `kind` / `data` / `files: []`。只改内部 `BUNDLE_VERSION` 不足以阻止旧引擎重写，因为旧引擎不校验该值；因此仅标记载荷升级到已认证信封 v2，普通载荷保持 v1，新引擎双读，旧 v1 客户端明确拒绝 v2。

## 影响

正面：

- 主目录内的目录与单文件在选择时就得到可移植身份；旧本机配置不要求用户逐条重新选择。
- 不同用户名、操作系统或自定义 DSH 根目录可以使用同一 `~/…` 身份；同一路径的安全表示变体不会重复加入卡片。
- 默认 DSH 根格式的旧远端数据可被有限识别，而任意外部绝对路径的兼容行为和风险都公开可见。
- 不新增依赖、RPC 或 bundle/文件行格式；普通载荷保持信封 v1，只有需要保护路径角色的载荷使用信封 v2。文件不被删除，读取失败与主目录未知仍按保守策略处理。

代价与限制：

- 旧远端的未知自定义 DSH 根无法自动判断，需要用户显式改用 `~/…`，或保证各机相同绝对路径。
- 未升级的版本仍可读写普通 v1 载荷；遇到标记外部路径的 v2 载荷会拒绝同步，避免静默丢失路径角色，但这要求使用支持 v2 的版本继续同步这类条目。
- 任一真正不可读的选择会暂缓整个附加分片，而不是像旧实现一样试图逐条带过；单一目录哈希不能证明未知部分，其他 profile 分片仍可同步。
- 旧状态缺少可验证目录基线，且双方内容都变化时，自动同步会停止，需要先导出本机备份再明确选择服务器恢复，不能承诺无条件迁移。
- 外部路径警告在启用同步时持续展示；这不是一次性失败，而是无法自动映射的固有限制。
- 本记录说明决策与兼容边界，不宣称尚未运行的核心测试、全测、typecheck 或 build 结果。
