# 0083 — 同步前后交接浏览器持有的模型显示状态

状态：已接受

## 背景

供应商顺序、模型顺序和供应商启停由 `dsh-model-think-level` 的浏览器存储持有，再延迟 400 毫秒写入 `ui-order.json`。WebDAV 只读取文件；用户刚拖动就同步时，快照可能早于 POST 落盘。同步写入文件后，配置插件又只靠轮询或焦点变化采用，页面会暂时保留旧显示。配置插件还存在等时间戳内容冲突回推、乱序 POST 降低时间戳及旧世代未成功请求被当成已保存的问题；这些在对应仓库修复。

## 决策

- 卡片的预览、同步、恢复、撤销、上传、导出、导入请求前派发可选的 `dsh-webdav-sync:before-snapshot`。同页插件同步注册 `detail.waitUntil(promise)`；等待保存结束后才发快照请求。
- 交接失败或超过 30 秒则释放忙碌状态并提示错误，不读取旧状态继续同步。关闭同步的 epoch 检查仍生效。
- 成功的同步、恢复、撤销、上传、导入后派发 `dsh-webdav-sync:applied`，让配置插件立即重新读取文件。拒绝的请求不通知成功；该事件不是新的用户编辑。
- 没有监听者时返回 `undefined`，不引入额外 await，保持两个插件独立安装以及原有动作启动时序。
- 不改变备份格式、配置白名单、文件冲突规则或模型删除语义，不把排序偏好中的旧 ID 误当成实际模型。新增两机器模型/供应商删除及重复同步回归。
- 不增加虚假的 `settings/document-updated` 或额外宿主重载：运行宿主默认 HMR 已监听 profile/home patch，配置重载后共享模型目录会自动刷新。

## 影响

- 当前页面待保存的顺序和启停进入手动操作快照，文件赢家及时回到浏览器；保存失败不会伪装成成功同步。
- 协议是同页面、可选的协作，不覆盖其它浏览器标签页，也不改变宿主定时同步。后台同步仍依赖配置插件原有自动保存与轮询。
- 两个插件均需使用包含本次修复的客户端产物。仅修改源码不代表已部署到运行环境；本次不升版本、不发布、不修改用户配置。
- 保留 0080 对独立配置文件仲裁及较新 `savedAt` 不回退的约束。
