# 0065 — 同步最后生效的模型覆盖配置

状态：`已接受`

## 背景

另一台设备同步模型配置后顺序不同。`0063` 已将 `providers` 的声明顺序纳入模型哈希，显式 `models` 数组也天然保序；加密传输使用普通 JSON，并不会排序对象键。因此不能仅凭显示差异再添加一个假想的排名字段。

本次用重复 `llm-pi-ai` 覆盖行复现了确定的同步错误：`collect` 取第一行配置，`applyPatch` 却按 id 取最后一行。Loader 按行依次覆盖实际存在的字段，`config` 整体替换；后行没有 `config` 只修改元数据，不取消前行配置。源机可能上传早已被覆盖的旧供应商/模型顺序，目标机写回后又采集旧配置，造成错误基线。显式后置 `config: {}` 同样被忽略；只删除最后一行会使更早的旧清单重新生效。

对本机 DSH `0.2.1-rc.2` 的静态代码检查还确认：`models` 是数组，`modelOverrides` 是元数据映射，没有独立持久化排名字段；供应商配置序不等同于所有界面的显示序。热更新的 `registrationFacts` 会排序供应商，纯键序变化可能跳过路由重注册；设置目录先放内置 catalog，再补声明项；UI 将账号/官方供应商置前。未显式填写非空 `models` 时，模型来自宿主 catalog，目录版本差异也不由 profile 同步消除。本次未读取用户实际 profile，不能把重复覆盖断言为该设备唯一的现场原因。

## 决策

1. 模型采集和写回采用同一适用行规则：id 为 `llm-pi-ai`、不是 `insert` 块、`name` 缺省或假值或等于内置包名 `@deepseek-ai/dsh-llm-pi-ai`。按顺序选最后一个实际带 `config` 的适用行；没有任何 `config` 时，保持原有规则，将最后适用行当作空模型份。
2. 更新只改选定行的 `config`，保留前面的旧覆盖行和后面的元数据行。显式空配置也是有效覆盖。沿用 `modelsIdentity`、`reorderProviders` 和 YAML 节点合并，不改备份版本或分片契约；同样配置再次同步或导入必须逐字节不写。
3. `models: null` 延续「移除模型覆盖行」的语义，对所有适用行删除整行，防止旧配置复活。这也移除这些行里的 `disabled`、`inject` 等元数据，可能重新露出或启用继承配置；更新时保留元数据的保证不适用于删除。名称不匹配行、同 id 的插入块仍不编辑。
4. 维持原分片边界：所有原始模型 id 行不交给通用 `patch` 份。同 id 的名称不匹配行与插入块留在本地，不重新分类；通用 `keyOf` 仍按 id 标识，重新分类会造成重复行键冲突，此次不扩展通用 patch 合并语义。
5. 文档区分配置序和宿主显示序，修正 `0063` 对设置页的过强保证。验证普通同步、重启后的基线收敛、手动备份以及模型份与 patch 份同时应用。

否决只写第一行：后置配置仍会覆盖它。否决把第一、最后配置深合并：Loader 对 `config` 是整体替换，合并会复活已删除的模型。否决添加 `sortIndex` 或同步 UI 假想字段：没有对应宿主持久化证据。否决为触发热注册而往配置塞无意义字段、重排全部 loader 行或修改宿主：前者污染用户配置，后两者涉及跨 adapter 生命周期/全局顺序，超出本插件修复范围。

## 影响

- 正面：上传、下载和手动备份使用实际有效模型清单，不再丢失后置覆盖中的供应商与显式模型顺序；写回读回一致，后续同步收敛而不反复写盘。
- 正面：保留 YAML 注释、非空更新时的本地元数据与无效行；默认模型和插件自身配置仍不进入同步。
- 代价：此前基线记录首行旧清单的 profile，在首次使用修复版时可能被判为本机模型变化；仍按既有三方合并规则处理，覆盖前留档，不暗中迁移服务器历史数据。
- 边界：只处理 profile 中针对固定内置模型 id/name 的覆盖，不求解任意继承树或多 adapter 展示次序。配置同步正确后，宿主热注册与内置目录规则仍可能使显示不同；纯供应商重排可重启宿主复核，默认目录版本不一致时需显式模型列表才能固定配置顺序。
- 后续：本文只处理 profile **内部**的覆盖行。宿主还会把 `$DSH_HOME/cordis.patch.yml` 排在其后并整体替换 `config`，家层带清单时 profile 的清单被整行遮住，表现为「同步了、重启也不变」；这一层由 [0071](0071-sync-the-catalog-where-it-takes-effect.md) 接管（按最后一层读写、两层都有时删掉家层那行）。
- 回归：`tests/store.spec.ts` 覆盖最后有效配置、后置空配置、名称 guard/insert、metadata-only、全分片原样往返、更新注释保留与整组删除；`tests/engine.spec.ts` 覆盖双设备上传/下载、provider 与 model 纯重排、重建 engine 后 no-op；`tests/manual-backup.spec.ts` 覆盖重复覆盖的导出/导入及重复导入不改字节。
