# 0057 — 自动同步复用实时凭据，密钥读取失败不推进密钥基线

- 状态：`已接受`
- 日期：2026-10-21
- 相关：[0009](0009-rescheduling-auto-sync-timer.md)（定时器）、[0019](0019-session-password-not-remembered.md)（会话密码）、[0039](0039-the-card-says-check-and-sync-apart.md)（两个时间与轮询）、[0054](0054-sync-api-keys.md)（托管 API 密钥）

## 背景

用户报告 API 密钥一直显示「仅本机有改动」，同时「上次检查」和「上次同步」时间不一致。自动同步原先只读取 `sync.json` 后直接构造引擎，没有传入宿主的 credentials 服务，也没有回填本次运行中未落盘的 WebDAV 密码。手动路由使用的引擎则有这两项，所以存在手动可用、定时器不可用的分叉。

密钥读取失败也不能当作一次成功测量：服务暂时不可用时，本机快照可能缺少整个密钥分片或只读到其中几项。若参与合并或记录为新基线，可能覆盖服务器此前正常上传的密钥，或让服务恢复后的待同步内容被误认为已经处理。

时间本身遵循 0039：「上次检查」是最近一次同步尝试，成功但没有内容交换时不推进「上次同步」。卡片每 15 秒轮询，保留未保存草稿，但刷新状态与两个时间；不能把两个字段改成同一个值来掩盖自动同步漏带凭据的问题。

## 决策

1. 定时器接收与手动路由共用的异步引擎工厂，每轮重新取得配置、宿主 credentials 服务和会话密码，再按最新 `autoEvery` 判断是否同步。不能只在启动时捕获服务，否则服务晚于插件上线后仍不可用。
2. 普通同步发现任一密钥读取问题时，整份 keys 暂缓合并，本机部分读数不上传，服务器已有的 keys 原样随其他分片保留。首次空服务器不写入不完整的 keys，其他分片仍可同步。读取问题必须出现在操作结果中，包括无改动的快速返回路径。
3. 初始快照或写后复读无法完整读取密钥时，保留此前 keys 的本地、远端比较基线，并清除条件读取所用的服务器版本。另记录 `keysBaseline`：它区分“本机曾测量过密钥（即使结果为空）”与“从未有可信密钥基线”。首次密钥读取失败时其他分片仍可建立状态；服务恢复后把服务器 keys 当作首次可知的基线并应用到本机，不能让 keys 的本机优先冲突规则把远端独有值覆盖掉。恢复时重新读取远端正文，避免 304 将尚未应用的远端密钥隐藏掉。其他分片照常记录。
4. 不改 `last` / `moved` 的既有语义，不改卡片运行时代码。补充真实定时器与 FakeDav 集成测试，验证首轮和后续密钥上传、服务晚到、仅会话密码、关闭自动同步，以及无改动时只推进检查时间。补充服务失联/部分读取失败恢复与客户端草稿轮询回归。

被否决的备选：

- 只给定时器传一次 credentials：不能覆盖服务晚到或替换，也容易再次漏掉会话密码。
- 把读取失败当成空密钥或上传已读取的子集：无法区分真正不存在和暂时读不到，会破坏远端已知完整的副本。
- 密钥失败就终止所有分片：其他配置仍可安全同步，没有必要一起阻塞。
- 每次检查都刷新「上次同步」：抹掉真实内容交换的时间，违背 0039。

## 影响

- 自动与手动同步取得相同的实时凭据，不再出现定时检查持续执行但漏掉托管 API 密钥的分叉。未勾选记住的 WebDAV 密码仍只驻留内存。
- 密钥服务短暂失联或部分读取失败不会用空/部分分片覆盖远端密钥；恢复后保留待比较的基线，继续合并。
- 密钥暂缓时其他分片仍可能完成同步，因此结果必须同时保留密钥问题，不能将其他分片成功解释为密钥已同步。
- 首次密钥读取失败与已测量为空由 `keysBaseline` 区分；首次恢复采用服务器副本，避免本机优先规则覆盖本机尚未读到的远端独有键。服务器版本会清除，可能增加一次完整备份读取/解封，这是保留待恢复内容的成本。
- 无内容变化时「上次同步」仍保持原值。只有自动同步真正传入密钥等内容后，该时间才随之推进。
- 不升级包版本，不改变备份格式、密钥只写不删或冲突时本机优先等规则。
