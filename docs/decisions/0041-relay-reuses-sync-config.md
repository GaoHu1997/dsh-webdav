# 0041 — 本机转发复用同步配置：一个开关、同一个保存、本地 Basic 账号

- 状态：`已接受`
- 日期：2026-10-20
- 取代：[0040](0040-local-relay-for-other-clients.md) 的独立配置文件、独立路由、独立保存与路径 token 授权决策；0040 原文保留为历史，不再作为当前使用说明
- 相关：[0003](0003-secrets-in-state-file.md)（主配置与凭据只存本机）、[0008](0008-browser-half-over-routes.md)（浏览器只走宿主路由）、[0019](0019-session-password-not-remembered.md)（上游密码可只留本次运行）、[0034](0034-extra-request-headers.md)（额外请求头）

## 背景

本机转发的目的仍然是让别的 WebDAV 客户端用上这里已经配置好的服务器与额外请求头，特别是只有地址、账号、密码三个字段的客户端；不是把其他程序的备份格式纳入 DSH 的同步、合并或恢复。

0040 把它做成另一套配置：再填一次目标地址和请求头，独立保存到 `relay.json`，另有状态与保存路由，客户端靠 URL 中的 token 进门。这与「复用已有同步 url/user/password/headers」的需求相反：配置重复、两个保存容易混淆，还把可用的标准账号字段闲置了。用户要的是主表单最后一个复选框，开启后在下面用小字给出可复制的地址与本地账号。

端口和账号必须稳定。其他客户端会把地址与账号当作服务器身份，重启就改端口或重新生成密码会使其重新加入或无法登录；而本地账号又不能直接使用真实的上游密码，否则仍是在向各个程序散发上游凭据。

## 决策

### 一、转发是同步主配置的开关，不是第二份服务器配置

- 上游目标和凭据只取同一份 `SyncConfig` 中的 `url`、`user`、`password`、`headers`。不新增目标输入框，不要求复制填写这些字段。
- 本机开关 `relayEnabled`、端口 `relayPort`、本地账号 `relayUser` / `relayPassword` 全部保存在 `<profileDir>/.dsh-webdav-sync/sync.json`（`0600`，所在目录 `0700`）。这些字段与主配置一样只在本机使用，不上传、不成为备份分片。
- 主表单最后一个复选框控制转发，开启后小字展示地址、端口、用户名与密码；地址、用户名、密码分别有复制按钮，剪贴板不可用或复制失败时给出失败反馈，不让异常破坏表单。
- 共用主表单草稿、放弃改动与唯一的 Save。`/plugin/webdav-sync/config` 同时保存同步配置与转发开关/端口并应用；`/plugin/webdav-sync/status` 同时返回 `relay` 状态与本地账号。没有 `/plugin/webdav-relay/*` 独立路由、独立转发表单或独立保存。

### 二、默认端口 3426 持久化，只允许用户显式更换

`relayPort` 默认 `3426`，只监听 `127.0.0.1`；合法范围是整数 `1` 到 `65535`。它不使用系统随机端口，不在重启或端口占用时自动换一个。端口用不了时卡片报告错误；用户点「换一个端口」修改草稿，再用同一个主 Save 生效，并更新其他客户端中的地址。

显示地址由草稿端口和上游 URL 的基路径决定。例如上游为 `https://dav.example.com/dav/` 时显示 `http://127.0.0.1:3426/dav`；上游没有路径时只显示本机 origin。地址中不含 token，也不嵌入用户名或密码。草稿预览不是已生效的监听状态，实际是否监听与失败原因由宿主状态单独反映。

### 三、本地 Basic 账号首次启用并保存时生成，之后保留

首次 `relayEnabled: true` 保存时，如果尚无完整账号，则生成本地用户名和密码并存入主配置。正常后续保存、重启以及关闭后再开启都不重新生成；关闭只是停止监听，不清账号与端口。账号为了被填进另一个程序，必须能在卡片上显示并复制；这不同于仍只下发 `passwordSet` / `passphraseSet` 的上游 WebDAV 密码与加密口令。文档与测试示例不得包含本机实际账号或密码。

上游 `rememberPassword: false` 仍只决定上游 `password` 是否落盘：本次运行使用内存里的密码，重启 Host 后需重新输入并保存。本地 `relayUser` / `relayPassword` 一直保存在本机，不受这个开关影响，也不能替代上游密码。

### 四、本地认证与上游认证严格分开

- 请求先验证本地 Basic 用户名、密码；缺少、错误或不符合 Basic 的认证返回 `401` 与 Basic challenge，立即结束，绝不转发到上游。仅绑定回环不算权限边界，本机任何进程都可能访问端口。
- 客户端的 `Authorization` 被本地验证消费，绝不透传给上游。上游使用同步配置的 `user` / `password` 拼 Basic；若 `headers` 已显式提供 `Authorization`，优先用该值，不再自动补 Basic。
- 其他请求头按「配置先写、客户端覆盖」合并，保留客户端协议头优先的语义。双向去掉逐跳头及 `Connection` 指定的连接级字段；请求的 `Host` 使用上游，不能沿用本机地址。

### 五、只做流式转发，不接管 WebDAV 或备份语义

方法、请求体、查询串、条件头、状态码、ETag 按客户端与上游的请求/响应转发。请求路径已包含上游基路径时不重复添加，否则补上基路径；指向上游基路径的响应 `Location` 改回本机地址。这里不解析 WebDAV XML，不解封备份，不转换 magpie 与本插件的格式，也不触发 DSH 的三方合并。

转发器随 Host 运行，插件卸载时停止；应用配置与停止操作串行处理，避免重叠保存、状态读取与卸载留下错误监听器。无效目标或非法配置请求头安全失败并停止监听，而不是启动后等客户端请求才抛错；端口占用则报告监听错误，不自动随机换端口。关闭同步会清空上游 URL 并立即停止监听，但保留转发开关、端口与生成的本地账号。

开启、关闭或保存这些本机设置本身不发起同步，不改写、删除或转换上游数据。只有通过本地认证的客户端请求才会去访问上游，客户端发出的写入仍按其原有 WebDAV 语义执行。

### 六、旧独立配置不自动迁移

旧 `<profileDir>/.dsh-webdav-relay/relay.json` 不读取、不自动迁移、不删除；不能悄悄用旧目标覆盖用户现有的同步目标，也不延续旧 token 地址。用户确认现有主表单的上游配置，勾选转发并保存，再将新地址和本地账号填入客户端即可。整个切换不需要触碰服务器上的已有备份。

被否决的备选与理由：

- **保留第二份目标/请求头、独立 `relay.json`、路由与保存**：重复维护同一个服务器，违背复用已填同步配置与一个 Save 的交互要求。
- **保留路径 token，或增加专用认证头**：客户端已经支持 Basic 用户名/密码，没有必要再引入特殊 URL；专用头又回到了客户端不能配置额外头的原问题。
- **让客户端直接填上游账号，或透传客户端 Basic**：把上游凭据继续分散到各个程序，且本地账号会被误送到真实服务器。
- **启动时随机端口、端口占用自动换端口或每次保存重新生成账号**：让客户端已保存的地址或账号悄悄失效。必须由用户显式换端口并保存。
- **绑定所有网卡**：不需要向局域网提供借用已解开上游凭据的服务；该功能只供这台电脑使用。
- **自动导入旧配置或处理服务器数据**：旧配置的目标可能与同步目标不同，不能静默选择，更不应为切换本机转发重写上游文件。

## 影响

- **正面**：服务器地址、真实账号与额外头只维护一份，所有转发编辑都走主表单同一个保存；客户端只需复制地址与生成的本地 Basic 账号。
- **正面**：固定端口和保留账号避免重启或普通保存改变客户端身份；本地认证失败时不会消耗上游凭据或向其发送请求。
- **正面**：转发仍不参与备份格式与三方合并，切换配置不会迁移或改动服务器数据，0040 的历史依据仍可追溯。
- **负面**：DSH 必须开着；上游不记住密码时，重启后要先重输上游密码。显示的本地账号并不意味着上游认证已经可用。
- **负面**：本地账号明文保存在权限受限的主配置，并下发到卡片用于复制；拥有本机账号文件读取权限的进程仍可能取得它及上游凭据。回环与 Basic 不是抵御已控制本机的进程的隔离机制。
- **负面**：显式换端口或改上游基路径会改变客户端地址，需要用户同步修改客户端；新旧地址/账号不兼容，旧 `relay.json` 需用户自行确认后处置。
- **验证**：完整测试套件 12 个文件、359 例全部通过。
