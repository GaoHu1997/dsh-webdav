# 0024 没有基线时不拒绝同步，但要把被替掉的本机副本说出来

- 状态：已接受
- 日期：2026-10-16

## 背景

`syncOnce()` 用 `first = state.local === undefined` 判断"这是不是第一次同步"。`first` 为真时所有分片都算"服务器那边改了"，服务器的配置直接接管本机。

这正是"加入一台别人的电脑"时该有的行为，也是 ADR 0001 从 magpie 移植来的原样。问题出在同一个 `first` 还意味着另一件事：状态文件丢了或坏了。

状态文件不存在和有基线但两边对不上，从哈希上看是一模一样的：本机的哈希不等于服务器上的哈希。一个从来没同步过的空白电脑和一个已经改了三天配置、结果状态文件被误删的电脑，插件看到的画面完全相同。结果是后者的编辑无声无息地被旧副本盖掉，界面只显示"服务器上有改动"。

`applyMerged()` 其实会先调用 `keepBefore()` 把本机原样封存进 `sync/`，所以东西没有真的消失——但没有人在界面上被告知它去了哪里。静默的数据丢失和"保存了但没说"之间隔着的只有一句话。

## 决策

不改变合并语义。首次同步依然是服务器赢，那是加入别人的文件夹唯一说得通的答案。改的是把被替换的东西说出来：

```ts
let saved: string | undefined
if (conflicted) saved = await keepConflict(engine, snapshot, remote)
else if (first && here.length > 0 && !sameHashes(local, remote.hashes)) {
  saved = await keepUnmerged(engine, snapshot)
}
```

`keepUnmerged()` 是 `keepBefore()` 加一句"找不到就当没有"，返回封存目录。条件里 `here.length > 0` 是必要的：只有分片真的会被带进来才留档，两个世界本来就一样时不必在 `sync/` 里堆一份。

这一句把"静默覆盖"降级成了"有副本、有通知、路径写在通知里"。用户看见的是"这台电脑上原来的配置已经保存到 <路径>"，而不是一个没有解释的文件替换。

## 影响

正面：无论状态文件是被删、被恢复成旧备份、还是磁盘写坏了，本机的配置都不会无声消失，而且通知里写得出它在哪。`Restore` 和 `Undo` 也因此有东西可以放回去。

负面：加入别人的文件夹时 `sync/` 里也会多一份本机的初始配置。这本来就是"接管"该有的证据，而且它是被点名的。

被否决的备选：
- **用 `sync-server.dshsync` 缓存副本区分"状态丢失"和"首次加入"**。缓存存在就说"状态丢了，请先 Restore"或直接拒绝。问题在于缓存不是证据——profile 目录可以被整体复制过来，缓存跟着基线一起回到过去；而拒绝的代价是用户没法加入。宁可多留一份。
- **把 `first` 拆成两个状态**（`never-synced` 和 `state-lost`）。判据还是同一个哈希比较，拆开只是换了个名字。
- **丢状态时清空服务器副本**。那会毁掉唯一还在的、能证明服务器上有什么的东西。
