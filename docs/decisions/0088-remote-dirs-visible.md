# 0088 服务器上的附加路径可见，加入本机要人点一下

- 状态：已接受
- 日期：2026-11-04

## 背景

[A 机在「附加目录与文件」里选了一条路径并同步，B 机收到了文件，但卡片上看不到这条路径，B 机改完也传不回去](0087-portable-extra-path-identities.md)。原因不在传输：`dirs` 份只携带「路径 + 内容」，从不携带「这条路径要在这台电脑上同步」这个决定。每台电脑的 `sync.json` 是自己的（[0036](0036-extra-directories-part.md)、[0079](0079-home-relative-extra-directories.md)），接收机的 `config.dirs` 为空时，`moveCore` 把整个 `dirs` 判成 `off`：服务器副本只被带过、不被应用，也不进列表。用户看到的是「文件到了，但路径没出现」。

反过来的毛病同样存在：接收机如果已经选了别的路径，服务器上多出来的行会被整份写进本机磁盘。也就是说，一台电脑能不能改动另一台电脑的目录，取决于它碰巧选了几条，而不是取决于它的用户点了什么。

两端都缺同一个出口：**这台电脑不加入某条路径时，应当看得见它、并且不读写它。**

## 决策

### 1. 状态记住上次同步时服务器上的路径

`StoredState` 新增 `remoteDirs?: string[]`（便携身份，见 0087）与 `remoteDirsAt?: string`（ISO 时间）。`syncOnce` 不推送的分支、`push`（含 `upload`）与 `restore` 各自在写回状态时记录，来源是这次真正读到的 `DirsPart`。

这两个字段只留在本机 `sync-state.json`，**不进备份**：它是「上次看到的服务器状态」，和 `last`/`moved` 同类，属于本机观察而非用户配置。

### 2. 状态只报告没加入的路径

`StatusResult` 新增可选 `remoteDirs?: { paths: string[]; at?: string }`，内容是 `remoteDirs` 中不在本机 `config.dirs` 里的路径，按 0087 的 canonical 身份比较；一条都没有时不出现该字段。`status` 仍是纯本机查询：它不为了这块提示去请求服务器，卡片因此标注「上次同步时看到」并带上时间。

### 3. 加入是一次显式点击

卡片在「附加目录与文件」行下、本机路径列表之后列出这些路径，每条一个「加入本机」，另有「全部加入」。加入只改草稿里的 `config.dirs`：

- 按 0087 的身份去重，`~/notes` 与同义的绝对路径不会变成两行；
- 受 5 条上限约束，放不下的不加入，块内说明要先移除一条；
- **不自动勾选**该行的开关；勾着才能在下次保存后生效，块内照实说明；
- 不产生任何 RPC，保存仍走原有的一次 `/config`；
- 加入后就是普通路径行，可以「移除」，移除只表示这台电脑不同步，服务器与文件都不动（0036 的只增不减）。

否决了自动加入：对端写一条 `~/notes` 就让本机开始读写自己的 `~/notes`，等于让另一台电脑替这台电脑决定读写范围。

### 4. 不加入就不写

合并仍把服务器上的全部 `dirs` 行带着走（否则它们会在下一次推送时从服务器消失），但 `applyMerged` 写盘前按 `config.dirs` 过滤，只写本机加入过的路径。`restore` 是例外：整份恢复是「把这台备份落到这台电脑」的显式动作，也是新机器拿到文件的路径，不按列表过滤。

这条修正同时堵住了上面说的反向毛病：此前只要本机选了任意一条路径，服务器上其余路径的内容就会被自动写到本机。

### 5. 不同步 `sync.json` 本身

整份同步 `sync.json` 看似能一劳永逸，但它含 `url`、`user`、`password`、`passphrase`、`relayPort`、`autoEvery` 等每台电脑各自成立的字段，多机互相覆盖会互相打断账号与定时器；[0080](0080-plugin-config-files-and-order-conflicts.md) 也明确把 WebDAV 自身配置排除在同步之外。路径清单要跨机共享，但它和「这台电脑是否加入」必须分开，后者只能本地决定。

## 影响

- B 机现在能看见「服务器上有 N 条路径，这台电脑还没有加入」，并一键加入；加入后路径按各自 DSH 主目录解析、内容照常双向同步，原本「文件到了但不回流」的僵局解开。
- 行为收紧：服务器上多出、而本机没有加入的路径不再被自动写入磁盘。不会删除任何文件，服务器上的副本与内容保持不变；只是这台电脑停止「替别人落地」。
- 清单来自上次同步，可能落后于服务器；`status` 不因此联网，慢一拍比让状态刷新依赖网络更可接受（[0029](0029-status-says-only-what-it-knows.md)）。
- 旧的 `sync-state.json` 没有这两个字段时按「不知道」处理，不显示该块；首次同步/恢复后自然出现。
