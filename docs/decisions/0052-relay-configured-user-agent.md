# 0052 — 转发优先使用显式配置的 User-Agent，避免客户端默认 UA 触发 403

- 状态：`已接受`
- 日期：2026-10-20
- 调整：[0041](0041-relay-reuses-sync-config.md) 第四节的头合并优先级，以及 [0046](0046-relay-backup-file-extension.md) 保留的请求头规则；仅增加 `User-Agent` 的例外

## 背景

部分上游按 `User-Agent` 检查客户端类型。插件已配置可被上游接受的 Zotero UA，但 Magpie 使用 Go 默认 `Go-http-client/1.1`；现有「配置先写、客户端覆盖」规则使配置值失效。对相同目录发只读 `PROPFIND`，Go UA 经转发和直接访问均返回 `403 Client type mismatch.`，配置的 Zotero UA 则均返回 `207`。Magpie 把该 403 转成目录或权限的通用提示，容易误判为路径或账号问题。

## 决策

- 只调整转发请求的 `User-Agent`：在经过既有头校验与连接级过滤后，配置有该头时保留配置值，不被客户端同名头覆盖；头名按现有大小写无关逻辑比较。
- 未配置 `User-Agent` 时继续透传客户端 UA；客户端没有发送 UA 时仍使用配置值，不自动硬编码 Zotero 或其他产品标识。
- `Depth`、`If-Match`、`Content-Type` 等其余头继续客户端优先；本地认证与上游认证隔离、显式上游 `Authorization` 优先，以及 `Host`、逐跳头的过滤规则不变。
- 不改变同步自身的头合并逻辑，不修改用户真实配置或上游文件。
- 否决「全部配置头优先」：会覆盖每次操作所需的深度、条件头与媒体类型，破坏 WebDAV 语义。
- 否决「要求每个客户端手动改 UA」或「强制硬编码 Zotero UA」：前者在无额外头输入的客户端无法配置，后者会影响不需要该标识的上游，且忽略用户已有设置。

## 影响

- **正面**：显式配置的上游客户端标识真正适用于所有转发客户端，修复已复现的 UA 检查 403，保留原有本地账号和地址。
- **正面**：协议头优先级、请求体与备份数据不受影响；未配置 UA 的用户保持既有行为。
- **负面**：配置 UA 后，各客户端不能再用自己的 UA 覆盖它；需要使用客户端原始标识时须移除配置中的该头。上游是否允许实际读写仍由其自身权限和策略决定。
- **验证**：回归测试使用本地模拟上游按 UA 返回 403/207，覆盖常规与混合大小写头名、配置与客户端冲突、客户端无 UA、配置无 UA，以及客户端 `Depth` 和独立上游认证不变；不依赖真实账号或真实服务器。
