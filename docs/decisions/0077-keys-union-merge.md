# 0077 — 「API 密钥」两边都改过时按名字求并集，不再一方整份胜出

- 状态：`已接受`
- 日期：2026-10-29
- 接续：[0054](0054-sync-api-keys.md) 的第六份分片、[0076](0076-audit-fixes-fourth-pass.md) 抽出的 `moveFor`

## 背景

用户 2026-10-29 的原话：「另一台电脑同步后，提示 未检测到环境变量，请填写密钥，其中有 噜皮生图，MagpieGateway 两个供应商，primerelay 密钥名称未同步且多出来一个未存储的密钥」。

查下去发现，服务器那份是完整的：`keys` 里 `IMAGE_MLGB7_API_KEY_2`（噜皮生图）、`MAGPIE_GATEWAY_API_KEY_2`（MagpieGateway）、`PRIMERELAY_API_KEY_2` 都在，和 `models` 里各路由的 `apiKeyEnv` 一条条对得上。缺的是**另一台电脑上没落库**，而落不了库有一半原因在这个插件的合并里：

`keys` 这一份的「谁改了」判断用的是 `localChangedAt`，它对 `keys` 恒返回 `Number.POSITIVE_INFINITY`（`src/engine.ts` 的 `localChangedAt`），于是两侧都变时**永远** `take: 'mine'` —— 本机那份整份替换服务器那份，另一台新增的名字就这么消失了。

0054 里这条看似安全的理由是本机优先不覆盖用户刚存下的值。但它把两件不同的事混成了一件：**同名不同值**该有个先后，**不同名**根本没有冲突。而密钥这层偏偏又没有别的补救手段 —— 凭据服务不可枚举（0054 背景第 1 条），一旦名字被丢掉，插件无从知道「另一台还有三个名字没过来」，用户只能看到「未检测到环境变量」，然后手填一遍，名字还可能被填成新的（`_3`），旧名字留下一条「未存储」的残行。

## 决策

### 一、`keys` 两侧都变时按引用名求并集

新增 `unionKeys(local, remote)`（`src/keys.ts:177-189`）：先收 `remote.refs`，再收 `local.refs`，同名的后写覆盖 —— 即**同名本机值胜**，异名两边都留。空名、空值一律跳过（坏包不写入空值，`set` 本来也不收空值）。

`moveFor` 两侧都变的分支里，`sameJson` 判「本来就一样」之后，`keys` 走并集：并集与本机相同则仍是 `mine`（不必写回服务器），否则新 take `'union'`，把并集结果放在 `move.merged` 里带回。

### 二、`union` 既写本机也推回服务器

合并主循环新增 `case 'union'`：`merged[part]` 与 `applied[part]` 都是并集，并且 `there.push(part)`。这样一次同步之后两台电脑的名字集合一致，不会出现「这台有、那台没有」的下一轮再合一次。

写回本机仍然走 `applyKeys`：逐引用 `resolve`，值相同就跳过（只读层遮蔽时重写会被拒，而「说同一件事」不该报失败），不同的才 `store`，失败的进 `keysProblems` 不中断。**依旧从不删除**。

### 三、卡片说清「合到一起」和「存进来了什么」

- 预览：`PreviewChange.take` 增 `'both'`，文案「两边都改过，密钥合到一起（同名的保留本机的一份）」/「Both changed: the keys are merged (this computer’s value wins for the same name)」。
- 结果：`SyncResult` / `ImportResult` 增 `keysWritten?: string[]`（`src/wire.ts`），`applyKeys` 返回 `{ written, problems }` 一并给出**真的写进去了**的名字；卡片跟 `keysProblems` 并列一行「这次同步把服务器上的密钥存到了这里：A, B」。只有名字，没有值 —— 值不离开它被写入的那个凭据库。

### 四、被否决的两个备选

- **谁新谁胜**：密钥没有独立时间戳，只能借整份的 `created`/`localChangedAt` 去猜，猜错就是丢名字 —— 正是这个问题本身。
- **本机优先但把服务器独有的名字列入提示、让用户手填**：名字本来就已经在服务器那份里，让用户照着抄一遍是最差的补救；而且填空名会铸出 `_3` 这种新名字，旧名留下残行（正是用户看到的现象）。

## 影响

- **不判断谁更新**：密钥没有可比的时间戳（`state` 只记每份的哈希），按名字合并是这一层唯一说得通的语义。
- **同名本机值胜**意味着另一台同名改过的值不会过来；它自己那侧会看到同名键仍是本机值。这是刻意的：本机正在用的值不该被远端静默替换，而 `0054` 的「从不删除」也决定了没有第三条路。
- **并集只增不减**：任何一侧删掉的名字都会在下一次合并里回来。删密钥因此不是同步语义的一部分，只能各自在面板上删（与 0054 一致）。
- 新增的名字若在本机填不进（只读层遮蔽、无凭据服务），`keysProblems` 照旧报出来，卡片上「存到了这里」那行不会出现它 —— 两行合起来就是这次同步对每个名字做的事。
